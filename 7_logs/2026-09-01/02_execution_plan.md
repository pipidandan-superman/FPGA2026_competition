# 执行计划

## 历史紫光赛题二执行计划（保留，不作为当前主线）

### 阶段一：软件参考模型与标定

1. 使用真实 OV5640 输出采集棋盘格或圆点标定图。
2. 使用 OpenCV 求取相机内参、主点、焦距和径向/切向畸变参数。
3. 生成固定测试图、软件矫正图和参数文件，作为 RTL 对照基准。
4. 记录每组输入图像、参数、输出图像和完整命令行日志。

### 阶段二：单路 FPGA 矫正闭环

1. 在 RK3568_MES2L100H 上确认摄像头输入、帧缓存和 HDMI 输出链路。
2. 先实现固定姿态、二阶径向畸变的定点坐标映射。
3. 加入双线性插值，处理边界、空洞和黑边。
4. 与 OpenCV 逐像素或误差统计结果对比。
5. 测量端到端延迟、帧率、资源和时序裕量。

### 阶段三：高阶功能

1. 通过上位机指令或 IMU 更新旋转/倾斜参数。
2. 增加动态矫正和参数切换的 CDC、缓存一致性和画面稳定性验证。
3. 视资源和时序结果，探索多路视频并行处理。
4. 视平台算力和模型部署条件，探索神经网络辅助增强或识别。

## 模块责任划分

- FPGA：视频流、帧缓存、坐标映射、定点运算、插值和实时输出。
- RK3568J：标定参数、配置管理、姿态/上位机控制、测试记录和可选神经网络推理。
- 上位机：标定、参数下发、图像质量分析和实验数据归档。

## 主要风险与回退

- PDS/Logos-2 不兼容 Xilinx IP：改用自定义 RTL、片上 RAM 和平台原生视频接口。
- 乘法器和坐标映射时序不足：改用查找表、分段近似或多级流水。
- 多路视频资源不足：先保证单路 640×480@30fps，再评估并行度。
- 神经网络无法稳定部署：保留为扩展模块，不影响赛题二主体验收。

## AMD 具身智能原型验证硬件规划

### 第一阶段：利用 ViTA 的 XC7Z020/Zynq-7020 完成原型

1. 以 ViTA 已验证的 `XC7Z020 / Zynq-7020` 为基线，确认当前工程的 DDR、时钟、以太网/USB/串口、扩展 IO 和摄像头输入方式。
2. 先完成单路摄像头输入、图像预处理、CNN 推理和 HDMI/网络输出。
3. 选用具有公开通信协议的机械臂控制器，优先验证 Ethernet TCP/Modbus TCP、RS-485/Modbus RTU 或 CAN 中的一种。
4. 由板卡发送目标坐标/动作编号，读取机械臂当前位置、执行完成、限位和故障状态。
5. 完成“识别目标—发送抓取指令—机械臂动作—反馈状态”的最小闭环。

### 第二阶段：迁移到 AMD 合规平台

1. 将视频预处理、畸变矫正、低延迟数据通道和实时 IO 迁移到 AMD FPGA/Zynq/Versal 平台。
2. 将 AI 推理、任务规划和上位机界面迁移到 AMD Ryzen AI PC。
3. 重新测量端到端延迟、识别准确率、抓取成功率、通信稳定性和资源占用。

## 当前主线的实现顺序

1. 从 ViTA 工程抽取 OV5640、VDMA、HDMI、PS+PL CNN 和 PS-only CNN 的可复用模块。
2. 在 XC7Z020 上先完成单路视觉识别和机械臂控制器模拟通信。
3. 接入真实机械臂控制器，完成高层动作指令与状态反馈。
4. 增加坐标标定、抓取动作和安全状态机，形成真实物理闭环。
5. 再将普通 PC 端推理迁移到 Ryzen AI PC，并补做正式指标测试。

### 建议硬件分工

- AI PC：模型推理、目标检测、坐标计算、任务调度和界面。
- AMD FPGA/Zynq：视频采集、矫正、预处理、数据打包、实时 IO 和看门狗。
- 机械臂控制器：轨迹规划、关节伺服、执行器安全控制。
- 机械臂：执行抓取、搬运或分拣。

## Python 与 PYNQ 方案边界

- Zynq-7020 的 ARM PS 可以运行 Linux 和 Python，但当前 ViTA 工程主要是 Vivado/Vitis PS-PL 方案，并不自动等于 PYNQ 工程。
- 初期优先采用普通 PC Python 完成 AI 推理、坐标计算和协议模拟；Zynq 侧保留现有 Vitis C/C++ 或 RTL 实时链路。
- 若需要在板上运行 Python，再确认 EES-331 的 Linux 启动、网口/串口驱动和 PYNQ 镜像可用性；没有官方镜像时需自行移植，不把移植工作列为第一阶段必需项。
