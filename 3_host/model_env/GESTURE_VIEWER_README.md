# EES331 手势识别上位机 v1.0

## 从上电开始

1. 保留已验证的SD卡、摄像头和网线连接，FPGA上电后等待60～90秒。
2. PC有线网卡为192.168.240.2/24；板端为192.168.240.10，向PC的UDP5000发送OV56、640×480 BGR视频。
3. 关闭旧EES331_UDP_Viewer和其他UDP5000接收进程。
4. 打开发布目录中的EES331_Gesture_Viewer.exe。默认普通显示，收到完整且CRC正确的新帧后自动运行CPU模型。
5. 想逐项验证时，点击顶部“测试模式”。不需要命令行、不需要ENABLE_MODEL文件。

## 两种模式

普通显示：持续显示画面、检测框、当前中文预测与置信度。画面不镜像。没有可靠单一动作时提示无检测、冲突或左右不可靠，不把多个类别强行合成一个动作。无检测不等于证明没有手。

测试模式：停止、拇指向上、拇指向下、食指向上、食指向下、无手共六项。每轮点击开始按钮或按空格，3秒准备、5秒观察；至少15个独立新帧、连续匹配5帧，正类匹配率至少90%，无手至少98%。每项连续3轮通过后仍等待用户点击/空格确认才换项。失败归零连续通过计数，所有尝试保留。R或按钮重置当前项，需确认；最后一项通过后还需按空格确认完成。

切换出测试模式需确认，当前测试存为INCOMPLETE；再进入测试模式是一个新测试。测试完成后可切回普通模式。完成只表示交互门槛达成，不是独立泛化精度认证。与原先验收脚本不同，本程序不执行60秒原始视频数值验收；普通/测试模式均检查每帧组包与CRC，首次现场验收仍需确认视频颜色和动态正常。

## 中断与恢复

视频超过1秒没有新结果：清除旧画面与动作，不计分，未完成测试的当前项连续通过数归零。恢复后按提示重新开始。必要时点击“重新连接”；FPGA重新上电、帧号从头开始时也应点击此按钮。

提示启动失败或端口冲突：先关闭旧接收者，再点击重新连接。不要同时启动两个实例；不需要更改模型或重装环境。

关闭窗口或Esc退出。未完成的测试不会记为通过。默认显示模式不输出控制；显式`--action-control`会启用以下AXI动作路径，但不控制机械臂。

## 第一版 AXI 动作控制

板端必须先加载已核验的动作BIT/HWH，并运行camera_action_v1.py，确认VIDEO_READY及ACTION_SERVICE_READY；仅启动PC端不能升级原SD启动的PL。不能将ACTL驱动附着到原视频Overlay。
源码启动：在已配置的固定环境中运行`gesture_viewer.py --action-control`；不要给人工测试加`--smoke-seconds`，该参数会自动关闭窗口。
完整路径为真实UDP视频→PC YOLO→3个不同新推理帧同类且各>=0.75→UDP5001→PS AXI寄存器→PL UART COM4及LED。PC不向COM4写动作。
Down/Stop/Thumbs Down/Thumbs up/Up对应LED1/4/5/6/7；左右不自动下发。同类保持不重复发；无有效动作1秒清灯，重新有效需再次稳定3帧。网络中断不保证清灯命令送达，不作为机械臂安全协议。
COM4为9600/8N1只读观察口。普通UDP接收器和本上位机不能同时占用5000端口；自动串口核验时关闭其他COM4程序。
自动实机证据入口`model_action_validation.py --run-dir E:/competition/4_metrics/logs/<new-run> --seconds 180`使用真实视频与模型，同时捕获COM4，保存预测/序号/字节比对；不能与GUI同时运行。其PASS仅覆盖该次观察到的动作，仍须检查stable_actions集合及用户LED确认。
2026-09-13已完成五种启用动作的真实模型/AXI/COM4对应，但热重载仍有独立已复现故障，详情见[板测报告](../../4_metrics/logs/2026-09-13_action_v1_end_to_end_run01/REPORT.md)。不以一次链路通过替代启动可靠性或模型精度验收。

## 日志与发布目录

每次打开程序自动在E:/competition/4_metrics/logs创建带时间戳的新目录，顶部“打开结果目录”直接进入。status.json记录实时状态，predictions.jsonl记录模型原始数值，events.jsonl记录用户切换/轮次/中断，test_001.json等保存完整测试尝试，result.json记录退出结果。只保存数值，不保存摄像头图片或录像。

这是Windows x64文件夹版：EXE和_internal目录必须放在一起，不能单独复制EXE。无需安装Python；在其他PC上仍需配置网卡、可写的E:/competition/4_metrics/logs路径，并重新做实机兼容性验收。当前固定PC CPU后端，不是FPGA内部推理。

## 已知限制

模型权重和阈值保持既有版本：best.pt SHA256为68db7cacbdd6d9c9a583e1c50a9f5934a3a6b78675b215ec86717827be8bfc79，640输入、conf0.45、IoU0.7。左右仅显示原始预测但不作为有效动作，食指向上仍可能误判拇指向上。此版本没有通过平滑隐藏原始错误。

## 构建

使用rebuild_environment.ps1在新的4_metrics/logs运行目录离线重建锁定CPU环境，再安装PyInstaller6.22.2构建工具。运行build_gesture_viewer.ps1 -BuildRun <该目录>。实际使用的构建工具wheel、安装报告、spec、构建控制台和验证记录应随运行目录保留。开发代码复用validated_receiver.py与manual_gesture_protocol.py，不修改冻结2_fpga。
