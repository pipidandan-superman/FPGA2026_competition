版本：2026-09-14 r3（数据下载结果与发布状态同步版）。结论状态：`DESIGN_PLAN_COMPLETE / MODEL_STATIC_PROFILE_PASS / DATASET_DOWNLOADED / PACKAGE_STRUCTURE_PASS / DATASET_SEMANTIC_AUDIT_PENDING / INTEGER_REFERENCE_NOT_IMPLEMENTED / QUANTIZATION_NOT_RUN / RTL_NOT_IMPLEMENTED / BOARD_NOT_RUN`。

本轮目标：只研究并规划当前七类手势YOLO在EES-331、`xc7z020clg484-1`上的完整PS+PL部署，保持已有摄像头与HDMI功能。现有PS网络发送作为共存背景负载，不扩展PC模型功能。静态模型分析已执行；本计划尚不代表量化精度、硬件资源或板测通过。

正式主路线：**浮点基线 → 硬件一致的整数参考 → 单模块验证 → 子图验证 → 整网验证 → 实时系统验收**，其中穿插小规模板测。数据准备、最低算术合同和环境锁定是前置/并行工作；PTQ、必要时QAT以及有依据的剪枝是整数参考阶段及其迭代的手段，不是必须依次执行的六个额外阶段。

r2统一了以下讨论：可以先开展软件工作、不必等完整RTL；公共手势数据可替代原配套数据；FP32精度、整数实现一致性和实时系统验收分别过门；golden同时包含逻辑张量和硬件打包合同；PS+PL承担完整任务不等于所有后处理都必须硬化。本版第4、9、10、12、13节优先于早期“PC预处理下放优先”和“等待队友训练集”的历史建议。

阅读入口：第4节是数据/量化/参考模型，第5–8节是计算与运行时预算，第9节是视频隔离，第10节是统一阶段与板测，第12节是交付物，第13节是当前状态和下一步清单。

## 1. 决策摘要

1. 从当前手势best.pt建立浮点基线和硬件一致的整数参考，先尝试INT8静态PTQ；精度不足才考虑针对性调整/QAT，性能或资源不足才考虑硬件感知结构化剪枝/微调。QAT和剪枝均不是默认必做步骤，不直接替换成来源不明的“YOLOv8-tiny量化权重”。
2. 原640输入保留为精度基线和低帧率兼容目标；**320输入作为首版性能候选**，416作为精度折中，256仅作更低成本对照。是否选320必须由同一真实手势数据集决定，尚未批准精度下降。
3. 采用**复用的INT8 GEMM计算阵列 + 卷积窗口/地址生成 + 向量/非线性算子 + 分块缓存 + 数据搬运 + 描述符调度**。只实现GEMM和激活函数不足以运行YOLO的分支图。
4. 首版目标结构为128个MAC通路（8输出通道×16空间位置）、100 MHz；每个通路按1个DSP预算，不预设DSP48E1能免费实现2/4路独立INT8 MAC。64通路用于可缩放验证，150 MHz仅为实现后优化候选。
5. PL运行63个网络卷积及相应特征处理；PS先以C/C++实现分类分数处理、DFL解码和NMS。完整检测闭环在板上，PC不参与这项推理。后续仅在后处理占比确实大时才进一步硬化。
6. 保持显示和推理异步：不要求摄像头产生的每一帧都推理，不让计算等待停止VDMA。框必须带帧号、有效期和模型版本。
7. 粗估资源可容纳**一个分块复用的INT8引擎**；无法全部片上保存现有权重和特征。640输入下首版并行度的理想卷积时间已超过300 ms，不承诺20/30 fps。
8. 原训练集不是PTQ硬性条件：有代表性的公共数据/自采无标注图片可校准；独立带检测框和正确类别的标注用于精度评估。数据未齐时仍可开发整数参考和导出器，但不能宣称正式校准或精度通过。
9. FPGA逐元素比较以明确的整数算法为golden，而不是任意INT8/QDQ运行时输出。先定义数值语义，硬件再遵守；允许先有逻辑张量包，后冻结总线/tile布局包。
10. 尽早穿插控制/DMA、单卷积和小子图板测，分别排除AXI/cache/布局问题；它们不能替代整网板测和连续视频验收。计划本身不构成任何一次上板、重配置或动作执行授权。

### 2.1 不同输入尺寸的算量

统一定义1 MAC=一次乘法累加；换算算术操作量可用2×MAC。本表只含63个主网络卷积，不含激活、池化、搬运、DFL与NMS；640全64个Conv的MAC为4,044,595,200，与ONNX静态统计完全一致。

| 方形输入 | 主网络GMAC/帧 | 候选位置数 | 最大单个卷积输出若INT8 | 原始检测头若全INT8 |
|---|---:|---:|---:|---:|
| 256 | 0.647049 | 1,344 | 262,144 B/256 KiB | 95,424 B |
| 320 | 1.011014 | 2,100 | 409,600 B/400 KiB | 149,100 B |
| 416 | 1.708614 | 3,549 | 692,224 B/676 KiB | 251,979 B |
| 640 | 4.044058 | 8,400 | 1,638,400 B/1,600 KiB | 596,400 B |

320等尺寸来自PT模型前向形状试验，现有固定640 ONNX没有被改写。算量随空间面积降低，不意味着权重数量也随之减少。640变320是否保持手指方向和弱类准确率尚未验证。

检测头卷积占主网络MAC的**36.677%**。320下stride8分支中有4个64->64的3×3卷积，每个58.9824 MMAC，合计235.9296 MMAC。优化应覆盖neck/head，不能只缩骨干。

### 2.2 实际算子覆盖

ONNX统计为Conv64、Sigmoid58、Mul58、Split8、Add8、Concat17、MaxPool3、Resize2、Reshape8、Transpose1、Softmax1、Slice2、Sub2、Div1。

57组Conv-BN-SiLU需要折叠与融合；其余Sigmoid/Mul包含头部评分或解码逻辑。PyTorch的SiLU实例被共享，`module_counts`显示1个对象不等于只执行1次；不能用模块对象数替代实际计算图节点数。实际结构还包括8个C2f、10个Bottleneck、1个SPPF（同一5×5池化连续调用3次）、2次nearest上采样。

证据：[静态结果](../4_metrics/logs/2026-09-14_yolo7020_deployment_plan_run01/summary.json)、[完整逐层profile](../4_metrics/logs/2026-09-14_yolo7020_deployment_plan_run01/profile.json)、[320卷积清单](../4_metrics/logs/2026-09-14_yolo7020_deployment_plan_run01/conv_layers_320.csv)、[ONNX节点](../4_metrics/logs/2026-09-14_yolo7020_deployment_plan_run01/onnx_nodes.json)。

## 3. 有没有能直接移植的轻量YOLOv8

有量化工具、结构化剪枝工具和FPGA实例，但r1选型检索未找到已经核实的“适配本EES-331、当前七类、完整YOLOv8、配套量化与调度及视频共存”的即用包。这里的“未找到”限于当时检索和README/官方文档检查，不表示世界上不存在相关实现；r2没有重新全面搜索或验收下表实现。

| 候选 | 可复用部分 | 本项目判断 |
|---|---|---|
| 当前YOLOv8n+静态INT8 | 已训练手势权重、数据合同、基线证据 | 首选。先把数值合同做对，再据性能决定是否剪枝 |
| 当前YOLOv8n+硬件感知结构化剪枝+QAT | 保留任务知识，减少实际通道和MAC | 第二步；通道按8/16对齐，并处理C2f/残差依赖 |
| 更小宽度/深度的YOLOv8派生网络 | 规则通道，更便于硬件规划 | 备选，需要重新训练/蒸馏，不能只改YAML后沿用原权重声称等价 |
| MobileNet/Ghost/depthwise等替换骨干 | 可能降低参数和MAC | 暂不优先：depthwise/group算子使稠密GEMM利用率下降，可能更慢 |
| INT4/二值低精度网络 | 存储进一步压缩 | 第二代研究；先建立W8A8精度和硬件基线 |
| LPYOLO/FINN实例 | 低位宽QAT和7020部署经验 | LPYOLO是改造TinyYOLOv3人脸任务，不是现有YOLOv8七类权重 |

具体参考核对：

- [Torch-Pruning YOLOv8示例](https://github.com/VainF/Torch-Pruning/blob/master/examples/yolov8/yolov8_pruning.py)提供C2f改写及结构依赖剪枝思路；代码含旧Ultralytics导入路径，须锁提交并适配8.4.142，不能直接安装后运行其默认COCO训练替代手势数据。
- [ONNX Runtime静态量化](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html)提供QDQ、校准与误差定位。QDQ文件本身不是RTL或板上执行器；非线性浮点回退仍需明确映射。CNN优先静态校准，避免运行期计算动态尺度。
- [Brevitas](https://github.com/Xilinx/brevitas)可以作为QAT候选工具；其版本、算子及导出图需要独立环境验证。首版不要求把整个流程切到FINN。
- [FINN构建流程](https://finn.readthedocs.io/en/latest/command_line.html)可参考量化和硬件验证方法，不能据可导入ONNX就认定已覆盖整个YOLO及本板平台。
- [SAR YOLOv8 FPGA项目](https://github.com/alan-turing-institute/sar-vessel-detection-fpga)提供训练/PTQ/QAT和HLS后处理，但目标KV260/Vitis AI3.5，硬件与本板不同。
- [YOLOv8-FPGA-Accelerator](https://github.com/nguyenchuyenhoa14-hub/YOLOv8-FPGA-Accelerator)README限定为7020检测头/解码/NMS加速；不采用其FPS作为完整YOLO网络的7020性能依据，也未把该仓库代码视为已审计RTL。
- [LPYOLO原作者摘要](https://arxiv.org/abs/2207.10482)说明其为PYNQ-Z2上的改造TinyYOLOv3人脸检测。
- [AMD历史DPU配置说明](https://docs.amd.com/r/3.2-English/pg338-dpu/Configuration-Options)可作为另一路线参考，但年代、工具链和算子支持都需匹配。当前用户选择自研GEMM架构，不把DPU作为默认依赖。

## 4. 模型处理与量化路线

### 4.1 顺序与候选包

按实验分支建立各自不可变的模型包（下列均为计划名称，不表示已生成；第4/5项仅在需要时启用）：

1. `gesture_v8n_fp32_640_ref`：当前权重、原标签、原640预处理，作为参考。
2. `gesture_v8n_fp32_320_eval`与`416_eval`：同权重先比较尺寸变化；必要时尺寸专项微调。改变尺寸的损失单独记录。
3. `gesture_v8n_w8a8_320_ptq`：最少结构改动，先PTQ。若误差过大，先定位敏感层/校准分布，再QAT。
4. `gesture_v8n_w8a8_320_qat`：训练中纳入目标舍入、饱和、SiLU近似和分支尺度。
5. 如第3/4步无法满足算量或帧率，生成`gesture_v8n_pruned_aligned_*`，剪枝后微调，再做PTQ/QAT。

这是“先验证量化，再决定结构改动”的决策路径；最终剪枝网络仍必须在剪枝及恢复训练完成后重新校准，不能复用剪枝前的激活尺度。

不建议第一步同时改输入、删检测尺度、换激活、换骨干和量化。每项变化应能独立归因。现有七类中的弱类应单独评价，不能仅凭总体mAP过门。

### 4.2 量化数值合同

- 权重：首选INT8、有符号、逐输出通道对称量化，零点0。
- 激活：首选INT8逐张量静态尺度。对称量化先作为简化候选，若精度不足再比较非对称输入或敏感节点，不为简化硬件强行牺牲精度。
- 累加：INT32，所有K分块先完成累加后再重定标，不能每块先INT8截断再相加。
- 偏置：BN折叠后的bias，以输入尺度×该输出通道权重尺度量化为INT32；需验证偏置和累加和的溢出界。
- 重定标：逐通道整数乘数+移位；乘法中间位宽、负数处理、舍入方式、饱和方式写入模型包。参考软件采用明确的round-to-nearest-even，硬件实现必须一致，若改舍入规则需同步重新生成golden并验证。
- 第一层输入：把`uint8/255`映射到目标尺度，可使用256项输入LUT/定点映射；避免FP32数据路径。RGB/BGR布局通过已知彩条确认。
- 卷积padding：填入代表浮点0的量化值（非对称时为zero_point）；letterbox灰边是114/255对应的量化值。这两个常量不可混用。
- 320模式预处理：640×480 -> 320×240 -> 上下各40行114 ->320×320；双线性采样坐标和舍入需与参考实现一致。是否采用area/nearest属于额外模型输入改动，须单独评价。
- MaxPool padding：带符号负激活时边界使用有效最小值/掩码，不能任意用0代替负无穷。
- 残差Add：先转换到共同尺度并保留足够中间位宽，再求和和饱和。
- Concat：不同输入可能尺度不同；先实现显式重定标和拼接基线。不能把“仅指针拼接”当作总是数值等价。
- 分类头和回归头可保持各自尺度，头部张量描述符分别记录；若强行合成71通道统一INT8尺度导致定位损失，应保留分离布局或局部更高精度。

最大卷积K=2304。对有符号8位直接乘加，忽略bias时粗界为2304×128×128=37,748,736，小于INT32上限；但偏置、非对称修正和累加实现仍需独立验证，不能仅凭这个算式删掉溢出测试。

若采用非对称激活，x_q-zero_point的差值可能需要9位表示；必须选择扩位乘法或等价零点修正，并重新核查接口/溢出和预算，不能仍按未修正的两个有符号8位值直接相乘。该候选不得静默改变已冻结GEMM语义。

### 4.3 SiLU、Sigmoid和DFL

SiLU是x·sigmoid(x)。首版保留其函数语义，用校准后的LUT或分段近似实现。推荐明确一个前激活量化点：累加->逐通道重定标到该层共同前激活尺度->SiLU表->输出尺度。256项表仅在输入被明确限制到8位域时才成立；不能声称256项能无误差覆盖任意INT32累加。

QAT或整数仿真必须包含该额外量化点。不能直接把SiLU改ReLU而不恢复训练。Sigmoid分类分数先由PS算，固定阈值可使用单调logit比较做等价早筛，但每通道尺度与阈值必须一致。

DFL为每框4个16bin分布：对每组16个logit做稳定softmax（减最大值），计算0..15的期望值，再按锚点和stride得到框。首版PS C/C++完成；不能误把reg_max=16当16个类别，也不能遗漏现有输出图中的解码逻辑。

#### 4.4.2 公共数据可用，但按用途准入

**可以使用网络公开手势数据集，不必等待队友训练时的数据集。** 原配套数据的优势是容易复现原始指标和类别合同，不是算法上的必要来源。PTQ用输入统计激活范围，并不重新训练出新的手势类别；校准数据代表性比是否来自原训练集更重要。[ORT静态校准机制](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html#static-quantization)

| 用途 | 是否需要人工标签 | 外部数据要求 |
|---|---|---|
| 校准scale/zero point | 不需要 | 接近部署输入的颜色、背景、距离、手部大小、光照；尽量覆盖目标七类和空场，不强制外部类别ID一致 |
| FP32/INT8检测精度评估 | 需要 | 正确类别语义及手部检测框；类别ID可重映射，不能强行改名造对应 |

| QAT/恢复训练 | 通常需要适配任务的监督数据 | 公共数据也可用，但先处理类别/框定义和场景偏移，不默认为现权重能直接兼容 |

当前类别映射固定为0=Down、1=Left、2=Right、3=Stop、4=Thumbs Down、5=Thumbs up、6=Up。Left/Right表示食指指向，不是左右手身份；左右翻转涉及方向标签变化，不能盲目镜像后保留原标签。外部握拳/OK/剪刀手等不能直接改名当作本模型七类；要改变类别集合属于重新训练/任务变更，不是PTQ。

### 4.5 剪枝原则

对稠密GEMM，非结构化置零不会自动减少周期或BRAM。优先整通道/整分支的结构化剪枝，通道按8或16对齐；输入RGB3和类别7等边缘维度用掩码处理，不改变模型语义。

建议用最终MAC降低20%/35%/50%做候选目标，而不是预设每层相同比例。C2f split、残差两端、Concat消费者必须依赖一致；检测头隐藏通道同样纳入敏感度分析，最终7类输出和64回归输出首版不剪。保留P3/P4/P5三尺度；删除某一尺度或改reg_max属于网络再设计。

评价目标是编译后周期和内存流量，而不只是参数数量。输出通道从64剪到61可能因硬件补齐仍按64计算；depthwise替代可能让稠密阵列利用率下降。蒸馏使用原FP32模型作为教师，可以作为恢复精度手段，但不是精度保证。

### 4.6 硬件一致的整数参考：先定义算法，再让RTL对齐

“同样使用INT8”不足以保证一致。本阶段产物是可执行的整数数值规范，不是只能在某个PC后端运行的压缩权重文件。定义三种参考并明确用途：

| 参考 | 用途 | 不可替代的边界 |
|---|---|---|
| FP32参考 | 验证原模型/预后处理和识别质量，衡量尺寸或量化损失 | 不要求与INT8逐元素相同 |
| QDQ/量化工具诊断图（可选） | 统计激活、试校准方法、定位敏感层 | 不能自动作为FPGA位精确golden，须检查融合/浮点算子/舍入 |
| HWINT整数参考 | 明确模拟PL可见输入、累加、重定标、非线性及输出 | 整数边界与RTL/板上回读逐元素一致；PS浮点后处理另定容差 |

最低冻结项包括qmin/qmax（有符号INT8是否使用-128端点也要写明）、signedness、axis、scale/zero point、BN折叠、bias量化、累加/乘法中间位宽、负数舍入、溢出策略、饱和位置、输入预处理、分支尺度、SiLU表及PS/PL边界。数值合同可以在RTL完成前确定；并行度/总线布局尚未最终确定不阻塞其开发。

单个输出的数学参考形式：

```text
acc = bias_q[channel] + sum_k((x_q[k] - z_x) * (w_q[channel,k] - z_w[channel]))
y_q = saturate_to_output_range(RNE(acc * M[channel] / 2^r[channel]) + z_y)
```

其中M/2^r近似Sx×Sw/Sy；该近似误差属于参考模型本身，不能在RTL中临时替换。bias只加入一次，不能每个K块重复加；按合同完成所有K块累加后才重定标。先定义数学RNE，再用正数、负数、恰好半单位、右移边界等测试证明位实现一致。若采用其他舍入方式或需要左移，必须明确合同版本和合法范围。

软件oracle建议用INT64完成安全中间运算并检查目标INT32/中间乘法位宽的范围；若硬件定义回绕/饱和，参考必须显式模拟，不能由宿主类型偶然决定。FP32仅能连续精确表示到2^24的整数，不能把普通浮点Conv输出直接冒充所有情况下精确的INT32累加；高速参考实现必须先与独立小规模整数oracle交叉验证。

推荐执行顺序：FP32图核对及BN折叠等价检查 -> 校准/确定候选尺度 -> 构建整数图与SiLU近似 -> 整网整数推理 -> 独立精度评估 -> 冻结模型包。QAT若启用，训练中的fake quant/STE不等于部署整数结果，导出后仍回到此流程。

### 4.7 软件到硬件逐级比对及首错定位

对少量固定真实帧保存可解释的FP32/整数对应节点；先检查输入，再检查每个算子/融合组的输入、acc、requant和激活输出。FP32与整数用反量化误差/饱和率/检测指标衡量，不要求整数相等；HWINT与硬件在约定整数边界要求`mismatch_count=0`，包括符号、shape、布局还原和有效尾块。

错误报告至少记录sample_id、graph node/layer、tile/M/N/K位置、张量坐标、expected/actual、quant_id、首次错误及总错误数。CRC/hash用于快速筛查，不能代替首次失败时的逐元素定位；只比较最终框可能掩盖中间错误被阈值过滤的问题。

定位顺序：原始输入/预处理 -> 权重和bias -> GEMM部分和 -> 重定标 -> 非线性 -> 分支/布局 -> raw head -> PS解码/NMS。出现首个不一致先停在该层，不同时改多层尺度或继续堆叠集成。独立模块测试用golden输入隔离模块责任，集成测试再用上游真实输出验证连接。

## 5. GEMM、特征处理和调度架构

### 5.1 数据通路

```text
PS：模型包校验/内存分配/命令提交/中断或状态处理/DFL与NMS
                         |
               AXI-Lite控制 + 描述符
                         |
DDR <-> AXI搬运 <-> 分块输入/权重缓存 <-> 卷积窗口/地址生成
                                                 |
                                      INT8 GEMM 8×16
                                                 |
                              INT32偏置/累加/重定标/SiLU
                                                 |
                         Add / MaxPool / Resize / Layout
                                                 |
                                     输出缓存 -> DDR
```

GEMM统一形式：`C[M,N]=W[M,K]×X_col[K,N]`，M为输出通道，N为输出空间位置，K=Cin×Kh×Kw（当前主卷积groups=1）。1×1直接映射；3×3用隐式im2col按需生成窗口。stride1/2、padding和行跨距必须配置。

**不要把全图im2col写DDR。** 本模型640下最大单层完整展开量达到3,686,400元素，320下也为921,600元素（按INT8分别约3.686 MB和0.922 MB）。这只是该层展开矩阵，不含原输入、输出与权重。使用行/条带缓存与分块窗口，避免9倍邻域展开造成的外存写入。

### 5.2 阵列与片上带宽

第一版阵列选Pm=8输出通道、Pn=16空间位置，K方向串行推进，128个MAC/clk。100 MHz理想吞吐12.8 GMAC/s。一次K步需要8个权重值和16个输入值，内部供数为24 B/clk，即100 MHz下2.4 GB/s；这是banked片上缓存带宽需求，不是要求DDR每周期供24个全新字节。

采用多bank、广播和空间/通道复用。先证明窗口生成与BRAM端口能持续供数，再提高MAC数量。K块建议从128/256起步，实际由bank布局选择；8×16的INT32局部和只需512 B，但必须保留跨K块累加状态。增加空间tile时相应扩大局部和和输入halo缓存。

当前shape计算表明8×16仅考虑矩阵边缘补齐的利用率：320约97.75%、640约99.99%；加入每个独立脉动tile的填充/排空后约90.82%和92.81%。这些不包括BRAM冲突、DDR等待、算子转换、调度开销，不能用作整机效率。

早层K=27等短归约尤其受脉动填充影响；实现可比较广播外积阵列与脉动阵列，保持相同整数接口。64通路8×8先完成可验证版本，扩至128时重新验证供数/布线。无条件增加到256通路不适合作为首版：按1DSP/MAC已超过220 DSP总量。

### 5.3 算子落点

| 图中操作 | 首版实现 | 要点 |
|---|---|---|
| Conv1×1/3×3 stride1/2 | PL GEMM+窗口 | Conv+BN离线折叠，激活就地流水 |
| SiLU | PL LUT/分段+重量化 | 4路向量作为起点；验证吞吐与过渡FIFO |
| 残差Add | PL向量单元 | 不同尺度对齐，溢出/舍入一致 |
| SPPF | PL MaxPool5×5，重复3次 | 行边界、负数padding、分支结果保存 |
| nearest上采样×2 | PL地址/重复输出单元 | 与导出Resize坐标模式一致 |
| Split/Slice | 编译期视图或搬运 | 所有消费者完成前不得释放源buffer |
| Concat | 第一版显式重定标/拼接 | 后续才优化为虚拟布局或tile融合 |
| Reshape/Transpose | 编译期布局/必要搬运 | 不是所有reshape都要硬件算子，也不是所有transpose都免费 |
| Sigmoid、DFL softmax/投影、框坐标 | PS C/C++ | 固定71通道raw head边界，量化参数逐张量记录 |
| NMS | PS C/C++ | 类别相关、阈值/排序/相等分数规则固定；先保持当前语义 |
| HDMI画框 | PL独立显示叠加 | 双bank框列表，帧边界切换 |

若某算子临时在PS回退，模型包应列出该节点和传输量，性能结果明示；不能以局部PL卷积完成等同全网络已映射。最终目标不保留在PS逐层运行大量卷积的隐藏路径。

### 5.4 描述符调度与离线编译

建议离线Python生成有限图执行计划，PS只提交一帧任务或一批层命令，PL负责内层M/N/K分块和数据依赖。禁止Python对每个tile反复MMIO控制。

首版描述符包含：opcode、input/output buffer索引与offset、形状/stride、kernel/padding、M/N/K、tile参数、weight/bias/scale/LUT偏移、输入输出量化ID、dependency/event、last/use和completion。二进制布局要版本化，不在RTL到处硬编码每层参数。

离线编译器负责：

1. 映射受支持ONNX节点，折叠BN及融合允许的激活；未知节点明确报错。
2. 为C2f/neck/head建立拓扑和张量生命周期。
3. 为feature buffers分配不冲突的空间，支持NCHW语义到内部通道分块布局转换。
4. 根据tile选择计算权重排列、tail mask、halo和跨行地址。
5. 处理Concat/残差的量化尺度衔接。
6. 输出`graph.json`、`schedule.bin`、`weights.bin`、`bias.bin`、`quant.json`、`lut.bin`、manifest/hash及golden测试。

调度器至少具有IDLE、校验、装载、计算、写回、完成、错误流程；错误需记录layer/tile/address/AXI响应与溢出计数。正式定义寄存器地址前从当前HWH分配空闲段，不复用现有ACTL/VDMA地址。首版限定一帧在途，避免早期多帧流水放大buffer依赖复杂度。

### 5.5 数值合同与硬件布局合同分层冻结

逻辑包先描述NCHW语义、量化轴和算子依赖；物理包随后明确通道分块、权重遍历顺序、M/N/K tile、行跨距、little-endian字节序、INT8二补码、INT32偏置/部分和格式、对齐、tail mask和DMA包长。两者以graph/node/tensor ID关联，不靠可变的导出节点名称或文件排序猜测。

导出器必须通过`unpack(pack(tensor)) == tensor`测试；补齐通道、空间尾块和halo在布局清单中可追溯，不能把无效补齐位置当作真实类别或候选。源模型、量化规则、输入尺寸变化会使数值包失效；只有Pm/Pn/AXI宽度/存储布局变化时，可复用数学golden，但必须重新导出物理包并回归分块累加、掩码和搬运。

运行时在提交前检查schema/ABI版本、模型hash、buffer边界、地址宽度、长度/stride与允许opcode；防止旧schedule搭配新weights或错误offset越界。模型包不兼容时明确拒绝，不采用静默默认尺度、未知算子CPU回退或错误尺寸截断。

### 6.3 DDR容量与访问预算

初步预留：权重及量化元数据4–8MiB；特征workspace16–32MiB；独立推理输入/诊断输出4–8MiB；调度与结果1–2MiB；合计新增池先按32–64MiB设计，编译器给出精确需求后收紧。额外大范围诊断dump按需开，不能默认占满CMA。

原视频CMA/VDMA地址窗口限制必须保留，使用实际`pynq.allocate`或受管理的DMA buffer，不硬编码裸机物理地址。当前兼容环境存在低地址DMA窗口约束；实际地址、最大长度、跨4KiB边界、对齐与cache维护要由HWH/驱动确认。

外存流量的一个可复现参考：把每个卷积输入/输出各物化一次，INT8权重每帧读一次（暂不计tile重读和非卷积），320约11.483MB/帧、640约36.929MB/帧。融合可减小，tile重载、Concat、SiLU单独落盘可增大；这些不是全网络外存流量的严格下界或实测值。

现有网口不会新增一个大的PL计算核，但PS分包、内存复制、GEM DMA仍是共存负载。首版不优化它，仅用原发送配置做并发检查。原视频S2MM/MM2S优先级及独立运行保留，推理DMA不能无限占用DDR。

## 8. PS运行时与本地检测结果

首版保留PYNQ/Linux作为控制环境，Python只用于交互/启动与测试；长循环调度、候选筛选/DFL/NMS用C/C++或等价低开销实现。不要假设当前x86 ORT CPU包可直接用于Cortex-A9，也不要求板上安装完整PyTorch。

检测输出分三尺度，320下40×40/20×20/10×10。PL写raw logits后，PS先处理分类阈值，再对保留候选做DFL和类别相关NMS。在单标签检测模式下，利用分类阈值先筛再解码应保持原语义；任何top-K截断、max_det变化都需与当前Ultralytics参考对齐并检查召回率。

## 9. 摄像头、VDMA及HDMI集成

### 9.1 分阶段接入与缓冲所有权

第一阶段独立推理用冻结的输入帧，不连接实时摄像头。全网络通过后，初次视频集成优先使用现有稳定快照逻辑生成独立推理输入buffer，保持摄像头环形buffer所有权。新增一次PS快照/拷贝是明确的首版代价，可测量，后续再改为硬件快照或受管理的环形缓冲，不能让推理读一个即将被VDMA覆盖的槽。

原VDMA写DDR并供MM2S显示；PS另读完成帧不是“HDMI经过PS CPU后分流”。首版软件快照先得到受管理的独立输入，新增推理搬运再读取它。后续若零拷贝读取视频环形槽，必须证明在整个消费窗口内不会被采集覆盖；仅拿到指针或一次cache invalidate并不保证一致性。

推理输入/输出至少定义FREE、FILLING、READY、IN_USE、DONE/ERROR状态及唯一所有者；发布完整数据和完成事件的顺序要有内存屏障。PS写给PL前flush，PL写后PS读前invalidate，具体按实际一致性端口/驱动约定；禁止DMA尚在途就释放buffer。帧号、模型版本与buffer generation共同校验，防止地址复用导致旧完成事件污染新任务。

### 9.2 连续显示与检测框配帧

显示模式建议：默认继续最新原始视频，并独立更新有时效限制的检测框；调试验收另提供“原帧保留、检测完成后显示配对框”的严格同帧模式。实时视频模式的旧框不具备严格同帧准确性，必须标记年龄、超时隐藏；第一版不引入未经验证的跟踪预测作为补偿。

原始帧更新率、检测率、HDMI刷新率和采集到结果/显示的延迟分别统计。完整位流下载本身会中断显示，运行期不通过反复重配置切换模式。推理局部复位、watchdog和错误处理不得复位视频DMA或摄像头时钟。

若要求每幅显示图严格匹配其检测框，就必须保留对应原帧并接受推理延迟/较低的新内容更新率；不能同时宣称“最新实时原图、零额外延迟、全部同帧框”。双bank框列表包含frame_id、数量、坐标/类别/分数和有效期，整表原子发布、显示帧边界切换，禁止画一帧时读取半更新列表。

ROI/缩放/letterbox保存原点、比例及四边padding，PS将网络坐标反变换回原图，裁剪到有效显示区域；后处理框坐标与PL画框的端点包含规则一致。过期/错误结果清空或隐藏，不能永久停留在旧框。

### 9.3 预处理、DMA和组帧问题的统一结论

预处理并非只能裁剪。缩放、letterbox、颜色/布局映射、输入定点量化和窗口生成都可在推理路径实现，同时保留原显示路径；关键是数据所有权、反压隔离和DDR预算，而不是算子名字。ROI会丢弃视野，缩放会改变目标细节，仍需单独精度评估。灰度/二值化不能直接替换当前三通道YOLO输入。

| 本轮早期问题 | 当前部署结论 |
|---|---|
| 两路图像是否必须再加完整VDMA | 不必。原图已在DDR时，推理用新增AXI读写引擎/AXI DMA访问独立快照、权重和特征；通道可调度复用，不是一层一套DMA |
| 预处理后另存一份图再上传/计算 | 如果确需独立写DDR，要S2MM/自定义AXI写通道；若预处理直接喂计算核，可避免该中间图落DDR，但网络中间特征仍可能需DDR |
| A.1帧/坐标管理原来由谁做 | 原视频行场时序在PL，PS负责完成帧快照/软件帧管理；新增采集frame_id/时间戳/完整性元数据是可观测性增强，不等于默认净提速 |
| A.2 letterbox原来由谁做 | 当前YOLO letterbox在PC Ultralytics路径，PS不是现有补边执行者；板上推理后可归入PL预处理，或先用明确的PS参考再迁移 |
| A.3 RGB-BGR-RGB是否有重复 | 原PL像素字段与DDR小端字节布局须区分；由RGB字段直入推理可避免多余交换，从BGR快照读则按合同重排一次，不假定PS做过颜色算法 |
| A.4 CRC/完整帧管理是否意味着PL组以太网包 | 不意味着。图像CRC/完成元数据、应用分包、UDP/IP和以太网帧是不同层；首版保留PS应用分包和网络栈/GEM发送，不实现PL Ethernet |

若使用AXI4-Stream视频数据接普通AXI DMA，必须明确视频SOF/EOL与DMA包结束的转换，不能直接把每行TLAST误当整帧完成。仅写图像不需要额外显示MM2S；具体通道数由并发/复用计划决定，不从“分成两路”机械推导两套完整VDMA。

流式优化按阶段推进：独立静态输入 -> 稳定PS快照+DMA -> DDR读取时融合缩放/量化/窗口 -> 必要时摄像头独立采样旁路。最后一种必须在帧开始判断接收能力，忙时整帧丢弃；若中途溢出则整帧标无效、丢到帧尾并重新同步。不能用有限FIFO来承诺承受无限推理停顿，不能通过共享TREADY把等待传播到视频主链。

本轮“提速”指端到端净收益：若PL预处理新增一份原图/补边图DDR写回、PS复制和第二路网络发送，收益可能为负。640补边会增加像素量，转FP32上传更会膨胀；第一版不为减轻PC预处理而额外发送完整中间图。GEMM前做按需预处理/隐式im2col，才有机会同时减少CPU工作和中间搬运；实际收益由分段测量确认。

### 9.4 网口共存与未来PC扩展边界

现有ACTL动作通路暂只沿用已明确的映射和去抖，网络部署阶段不增加机械臂动作功能。最终验收包括PC断开时板上模型仍独立工作；原网口发送保持配置即可，不扩展PC功能。

“现有网口没有占用很多PL资源”与“PS/DDR零开销”不同：保留其配置，作为CPU、内存与GEM DMA背景负载测量，不为本阶段额外重做协议。PL执行CRC并不自动解除现协议整帧校验带来的发送时机约束，也不自动绕过PS/DDR。

长远可让FPGA完成此YOLO、PC处理视觉语言模型或另一模型，但不是本阶段开工/验收依赖。显示输出处叠框不会自动改变DDR原图；默认保持干净原图并附frame_id/检测元数据，避免将画框图片作为其他模型唯一输入。若后续明确需要网络发送烧录框的视频，增加独立合成缓冲或叠加后回写并重新预算，禁止原地修改多消费者共享的原图。

历史RGB565单流传输、PC显示与推理解耦、另一YOLO/视觉千问等方案仅保留为后续扩展，不混入当前硬件移植范围。之前讨论和源码定位见[预处理与共享视频路径分析](../4_metrics/logs/2026-09-14_pl_preprocess_analysis_run01/REPORT.md)；其早期PC优先路线不再作为当前阶段顺序。

## 10. 分阶段实施与验收

### 10.1 唯一主路线与阶段映射

**浮点基线 → 硬件一致的整数参考 → 单模块验证 → 子图验证 → 整网验证 → 实时系统验收**，其中穿插小规模板测。

### 10.2 G1/G2：软件阶段先证明什么

1. G1固定真实输入字节及预处理结果，检查PT/导出图、BN折叠前后、raw head到最终框的对应；重复运行保存相同配置。当前合成输入allclose证据不代替这一阶段。
2. G2先验证量化/反量化、bias、乘加、RNE、饱和、LUT等独立函数，再接整数图。饱和率、INT32边界、激活误差和每类检测指标都记录。
3. 整数参考以独立小规模oracle交叉检查，防止软件参考与硬件共享同一错误算法而“互相通过”。随机种子与测试参数固定，包含人工可手算例子。
4. 校准方法、敏感层位宽/近似或输入尺寸变化后重新测精度；数值包冻结前的dump标EXPERIMENTAL。不能拿未冻结参数的文件开始最终RTL验收。
5. 首版可选约10–20个样例做全检查点深度dump，另选100帧以上固定真实回归样例做端到端重复性测试；数量是测试集规划起点，最终由覆盖/存储/精度要求决定，不要求全评估集都倾倒所有层。

### 10.4 G4/G5：逐段集成，不跳到最终框才检查

子图顺序建议：Conv+bias+requant+SiLU -> 连续Conv/Bottleneck -> C2f分支 -> SPPF -> 上采样+Concat -> 单尺度检测头 -> 三尺度raw heads -> PS分类/DFL/NMS。每段同时验证数值和输入/输出缓冲寿命；记录软件调度模拟器与PL调度器的事件顺序，允许合法重叠但结果依赖必须满足。

整网阶段分两个层面：G5a静态仿真/子图串联回放确认全图覆盖，G5b板上静态整网确认实际DMA、DDR和PS执行。仿真速度不足时可分层/分段保存一致的边界回放，不能因此省略板上完整端到端运行。测试跨帧buffer复用和顺序任务，不只测第一次上电的单帧。

浮点PS后处理不要求不同CPU数学库的每位相同：预先定义logit/坐标/分数误差容差、阈值比较、排序tie-break、NMS IoU比较规则与边界测试；远离阈值样例要求类别/框决策一致，边界差异单独解释。整数raw heads必须先通过，不能用放宽最终框容差掩盖PL整数错误。

### 10.5 穿插小规模板测，而不是最后才首次上板

| 板测节点 | 可插入位置 | 具体范围与证据 | 不代表什么 |
|---|---|---|---|
| B0 控制与搬运冒烟 | G2/G3期间，独立测试设计已仿真后 | ID/版本寄存器、已知模式buffer往返、DMA长度/端序/cache/中断、保护区未写坏 | 不证明任何神经网络算子正确 |
| B1 GEMM/单卷积 | 对应G3模块仿真通过后 | 小矩阵再真实层shape，回读acc/输出对golden，记录cycles/stall | 不证明C2f、整图调度或模型精度 |
| B2 代表性子图 | 对应G4子图通过后 | 含残差或Concat的短图，多任务buffer复用，回读首错和DDR计数 | 不证明整网/视频并发 |
| B3 静态整网 | G5b | 固定图片，所有PL网络算子+PS后处理，PC仅供离线调试文件/记录 | 不证明摄像头实时性和显示连续性 |
| B4 实时与长稳 | G6/G7 | 摄像头、HDMI、原网口负载及异常恢复，真实手势验收 | 只有该阶段才可声明相应整机通过 |

每次进入物理测试前先“检查状态”：确认板型、当前BIT/HWH/软件版本、运行服务、原始视频、可恢复基线及供电/连接；一次只给用户一个明确物理动作。实际加载/重配置需单独纳入用户授权的实施范围，本次文档请求不执行。使用独立可回退工程，冻结2_fpga不直接试改。

完整PL重配置可能中断原视频，必须安排受控维护窗口，不能声称早期测试期间也绝不影响显示。先停止相关DMA并确认停止，再释放缓冲；加载失败/首帧超时不自动重复下载，不通过整板反复复位绕过原因。原始预览若“花屏+卡顿”，停止推进推理测试，恢复原显示并定位采集/显示故障。

### 10.6 实时验收、停止条件和优化回归

验收分别记录功能、模型精度、性能、可靠性，不以一个PASS覆盖全部。性能统计固定warm-up、测量时长、输入分辨率、模型/量化版本、并发配置与时钟；只计不同新采集帧，P50/P95/P99/最大延迟和frame_age一起报告。跨时钟域时间戳先定义共同时间基准/换算，明确采集到结果、结果到显示、采集到显示三种口径。

至少覆盖正常负载、推理持续过载、空场/弱类/进入退出、多次启动、PC断开、原网口发送开关对照、推理超时/无效描述符等受控故障。HDMI无新增花屏/卡顿、VDMA无新增错误；UDP在相同网络条件下不劣于基线，而不是把非确定性网络零丢包作为不加条件的保证。记录推理丢帧率/最新帧策略，不隐藏排队积压。

资源/时序验收以实际集成后的实现报告为准：目标时钟约束完整、setup/hold满足、关键DRC/CDC问题已处理，资源保留诊断余量。读取可用的功耗/温度观测并记录测量条件，不能用仿真功耗代替实测热稳定性。

任一数据越界、DMA未停止、帧所有权错误、整数首差、持续视频异常或错误结果进入动作输出，停止扩大测试范围并保留证据。恢复到最后通过的模型包/位流/软件组合后再做单变量修复；剪枝、量化、融合和频率优化都必须重跑受影响的精度、数值、接口、资源及系统门，不能只凭FPS升高放行。

首版估计为约4–8周工程工作量（非承诺排期），取决于数据到位、GEMM核已有可复用程度、硬件仿真与QAT进展；其中先收敛数值/布局/调度合同，再实施完整RTL。已有其他项目的GEMM核可作为候选，但必须重新核对位宽、DSP48E1、接口和本网络tile，不把历史其他任务PASS继承到本模型。

## 11. 必补测试和容易遗漏的问题

1. **预处理**：相机RGB565高位扩展、BGR字节序、缩放坐标、letterbox偏移、0padding和114padding的不同。
2. **数值**：BN折叠、INT32局部和、跨K块累加、负数舍入、逐通道尺度、激活饱和、SiLU负区间、Pool边界。
3. **模型图**：C2f多个消费者、残差尺度、Concat布局、三个检测尺度、reg_max16与7类、无独立objectness。
4. **供数**：bank冲突、BRAM读延迟、窗口halo、图像宽度/通道尾块、AXI4 burst/4KiB边界/响应错误、ready/valid稳定性。
5. **内存**：CMA连续地址、cache flush/invalidate、DMA ownership与内存屏障、描述符版本、错误后停止DMA再释放buffer。
6. **帧一致性**：推理读取完成前不可覆盖；同帧结果和帧号绑定；显示列表帧边界切换；旧结果失效。
7. **性能**：cycle_total/compute_busy/input_stall/output_stall/DDR_bytes/PS_post_ms/frame_age，区分MAC理论吞吐与端到端。
8. **工具与部署**：从所选板证基线manifest/构建日志核实并继承实际Vivado/IP版本，不凭目录名推定版本或自动升级；选HLS时独立验证兼容性；PYNQ配对BIT/HWH和cache地址合同；旧热重载问题不通过自动重复下载绕过。
9. **资源**：INT8不等于DSP用量自动除4；LUT实现乘法也会转移到布线压力；用布局后时序和实际功耗，而非只有综合估计。
10. **准确率与动作**：七类分类/检测、空场误触发、距离变化分别统计；网络加速不会自动修复原数据弱类。
11. **数据与泄漏**：公共数据来源/版本/使用条件、语义映射、漏标、近重复、视频分组、真实场景偏移；最终测试不能参与校准或参数选择。
12. **参考可信性**：INT64小规模oracle、真实整数中间位宽、RNE ties、QDQ浮点算子审计；软件与RTL共享同一bug可能造成假一致。
13. **版本失配**：输入尺寸、scale、权重、LUT、schedule、layout、BIT/HWH、PS ABI一起关联；改数值重导golden，改布局重导物理包。
14. **验收统计**：低样本每类Recall波动、mAP扫描与部署阈值区别、不同新帧计数、暖机/时间戳、P99与最坏延迟，不能只报平均FPS。
15. **日志开销**：全层dump、ILA、Python打印和DDR回读会改变性能；诊断模式与性能模式同源但配置分开，性能关闭dump前后均跑正确性回归。
16. **复位与动作安全**：异常后DMA quiesce、缓冲generation、部分输出作废；模型测试不增加动作功能，故障/过期检测不能驱动新动作。

### 12.3 完整golden、容量控制和可复现性

采用三类测试集合：小规模全节点深度样例用于首差定位；算术/协议合成集合用于边界覆盖；较大真实回归/精度集合主要保存输入ID、最终输出、汇总指标和异常节点。不要对全部校准/评估图片无差别导出每层INT32张量；运行前按shape×dtype×样例数估计存储，并设显式dump选择和容量上限。

保存执行命令、Python/库版本、脚本/源权重hash、校准方法/采样seed、线程/后端设置。hash一致证明文件身份，不证明数值算法正确；差异检验仍需独立oracle/逐元素比较。整网诊断可按首失败层重新导出，不用永久打开全层DDR写回影响吞吐。

以下任一改变触发数值包重新生成及相应精度回归：权重/剪枝图、输入尺寸或颜色/缩放合同、scale/zero point、bias规则、舍入/饱和、非线性近似、PS/PL边界。只改总线/通道分块/tile布局则重导物理包并做搬运/分块回归；不把旧schedule、旧LUT、旧golden与新模型混装。

### 12.4 发布与阶段状态

每份报告同时写结果和范围，例如`MODULE_SIM_PASS / BOARD_NOT_RUN`、`SUBGRAPH_BOARD_PASS / FULL_NETWORK_NOT_RUN`，不能只写泛化的“通过”。数值或精度未验收的包用EXPERIMENTAL标记；资源预算是BUDGET，OOC是OOC，最终布局后时序和实机证据分别列出。本文所有NOT_RUN均指本次YOLO硬件移植，不否认历史视频基线已验证的范围。

候选包以“模型数值包+物理布局/调度+BIT/HWH+PS运行时”联合版本发布，附已通过门和仍未通过项。启动时拒绝不兼容组合；回退必须能恢复最后通过的整套组合，而不是只替换一个bit文件。历史证据只读保留；Git提交/发布或板卡重配置是后续单独实施动作，本次仅更新文档和工程记录。

### 13.2 不应阻塞开工、但需在对应门前冻结的决策

- 数据来源：可选公共或自采；未定位队友数据不再列为唯一阻塞。
- 输入尺寸：640为参考，320为性能候选，416为折中；选择依赖同集精度/资源/时延，不预先默许损失。
- 数值实现：W8A8为首选，激活对称/非对称、头部敏感INT16、SiLU精度由G2比较；参数未锁时只能发实验包。
- 性能与质量阈值：5次新帧检测/秒、P95≤250ms及第4.4节精度门均为待确认工程目标，不能事后改门槛来制造PASS。
- PS/PL边界：主网络算子在PL，分类处理/DFL/NMS首版在PS；将来进一步硬化须由占比和收益驱动。
- 显示配帧：默认实时原图+有时效框；严格同帧模式接受对应缓存/延迟。具体有效期、队列深度和后处理边界容差须在G5/G6前落表。
- 实现环境：核对实际工具链、BIT/HWH、地址空间、HP/一致性/cache合同和可用CMA；早期B0/B1验证，不等整网结束才发现平台不兼容。

### 13.3 建议的第一批软件工作包

1. 建立只读原权重manifest与独立输出目录，复用静态profile。
2. 基于已下载v6做语义与框质量审核、精确/近重复检查、跨集泄漏审查，建立独立路径配置与校准名单，并补真实摄像头场景；无需再等待登录或重新寻找首选包。
3. 固定预处理/后处理与640 FP32基线，再做320/416对照。数据未齐时先完成框架和合成边界测试，不冒充真实基线。
4. 实现量化合同、INT64 oracle和硬件整数算子，明确SiLU与分支量化；校准到位后跑完整整数参考。
5. 在同一独立评估集比较质量，通过后冻结逻辑模型包与深度golden样例；如失败按第4/10节首错定位，不立即剪枝重训。
6. 再生成与GEMM接口一致的物理包，进入单模块仿真和受控小规模板测。GEMM接口/IR设计可与前述工作并行，但不得把阶段证据提前宣称为完成。
