# YOLO INT8 PE 设计手册

版本：1.0，2026-09-18。对象：EES-331 / XC7Z020 上的新一代 YOLO 卷积计算单元。

本文是可实施的设计规格，不是新增 RTL 的验收报告。只编写手册，不修改冻结 FPGA 工程。配套阅读：[GEMM 设计手册](yolo_gemm_design_manual_20260918.md)。

## 1. 范围与设计选择

PE 的职责是计算一个输出通道、相邻两个空间位置的两个整数乘积，交给两路独立累加器。本文把“一颗 DSP 的双乘积核”称为 PE，把“PE + 两路累加状态”称为 MAC 单元。

采用同权重双激活打包：一个 DSP48E1 计算 w×x0 和 w×x1。不是任意两组乘法，也不是 DSP SIMD 模式下的双乘累加；两路 INT32 累加在 DSP 外部完成。SiLU、偏置、重定标属于共享尾部，不在每个 PE 内复制。

| 项目 | 基线规格 | 状态 |
|---|---|---|
| 权重 w | signed INT8；当前包范围 −127…127 | 软件合同 |
| 激活 x0/x1 | signed INT8，−128…127 | 软件合同 |
| 打包乘法 | 同一 w 乘相邻两个空间位置 | 旧 PE 已实现，本轮作为复用方案 |
| 独立乘积 | 数学值 signed 16 bit；解包阶段使用 17 bit | 新旧一致 |
| 累加状态 | 每个输出位置 signed INT32 | 软件合同 |
| 吞吐 | 输入不缺数时每拍接受一个三元组，输出两个乘积 | 设计目标 |
| DSP 数 | 每个双乘积 PE 一个，不包括尾部重定标 | 资源基线 |
| 背压 | 固定延迟核心 + 有效位流水 + 外部信用控制 | 推荐新接口 |
| 延迟 | 旧原语路径为 3 级寄存流水；新增解包寄存会再加一级 | 必须由接口时序测试锁定 |

单乘积/单 DSP 可作为对照实现，但不作为面积优先默认方案。

## 2. 数学合同与位宽

对 OC 行 o 和空间位置 n：acc[o,n] = Σ(k=0…K−1) W[o,k]×X[k,n]。

PE 内不做浮点计算、不做饱和、不做 INT8 截断，也不提前加入偏置。所有 K 分块积累完毕后，GEMM 尾部才加一次 bias_eff，再做重定标和可选 SiLU。

| 信号 | 位宽 | 有符号 | 解释 |
|---|---:|---|---|
| w、x0、x1 | 各 8 | 是 | 输入字节 |
| x0b | 8 | 否 | x0+128，等价翻转 x0 最高位 |
| A | 25 | 是 | x1×2^17+x0b |
| B | 18 | 是 | w 的符号扩展 |
| P | 43 | 是 | A×B；DSP P 端口 48 位，按合同取有效位 |
| lane0_raw、lane1_raw | 各 17 | 是 | 用于解包和修正 |
| w_shift7 | 17 | 是 | w×128，先扩位再移位 |
| p0、p1 | 各 17 | 是 | 推荐边界位宽；有效值适合 signed 16 |
| acc0、acc1 | 各 32 | 是 | 两路独立部分和 |

不能在 8 位表达式内完成 w 左移 7 位；不能依赖拼接表达式自动保留 signed 属性。每个乘积必须符号扩展到 32 位后再与累加器相加。

## 3. DSP48E1 双打包原理

定义：

    x0b = x0 + 128
    A = x1 × 131072 + x0b
    B = sign_extend(w, 18)
    P = A × B
    p0 = signed(P[16:0]) − 128 × w_delayed
    p1 = signed(P[33:17]) + P[16]

A 的 25 位布局为 x1[7:0]、9 个零位、x0b[7:0]，不是把两个 signed INT8 直接拼接。低通道变为无符号以后，避免把 x0 的符号扩展污染到高通道。

低乘积 L=w×x0b。即便覆盖 w=−128，L 的范围也只有 −32640…32385，适合 signed 17。L<0 时，高通道的算术商少 1，P[16] 正是这一借位修正；低通道减去 128w 恢复原来的 w×x0。

例：w=−3、x0=−5、x1=7。x0b=123，L=−369；低通道 −369−(−384)=15，高通道先得到 −22，补借位 1 后为 −21。结果分别等于 (−3)×(−5) 与 (−3)×7。

**禁止直接对打包的 P 跨 K 累加后再解包。**低通道随 K 累加会产生跨通道进位，两个独立 MAC 的语义不再成立。必须每拍解包，分别累加。

## 4. 原语配置与流水线

复用现有 PE 的乘法配置：AREG=1、BREG=1、MREG=1、PREG=1；ACASCREG/BCASCREG 与输入寄存配置一致；USE_MULT=MULTIPLY、USE_SIMD=ONE48；选择纯 A×B 的控制组合。原语未使用端口必须按所用 Vivado 版本的原语模板连接，不能将旧源码注释当作全部合法参数证明。

本轮官方在线检索失败；原语配置依据项目内已有实现及此前证据，未新增器件手册逐条合规结论。参考文档标识：AMD UG479、UG953；正式实现时锁定具体版本。

推荐将时间定义为“上升沿采样”，不要只写含糊的 D+3：

| 时刻 | 对同一个输入事务 T 的动作 |
|---|---|
| E0 | 输入在此前稳定，E0 被 A/B 输入寄存器采样 |
| E1 | T 的乘法结果进入 M 寄存器 |
| E2 后 | T 进入 P 寄存器，组合解包得到 p0/p1 |
| E3 | 下游累加器采样 p0/p1；有效位、lane mask 对应 T |

从 E0 前的呈现周期数起可称三拍路径；从 E0 到 E2 的边沿差为两拍。TB 必须使用上述采样事件，避免文字计数差一拍。

若在解包后加寄存器，则 E3 捕获修正乘积，E4 才累加。w 的延迟必须与 DSP P 对齐；valid、mask、first_k、last_k 和 tile context 同步移动。延迟只改变时序，不改变数值。

推荐固定运行流水：空拍有效位为 0，DSP 可继续计算无效输入。若采用统一 CE 停顿，必须同时冻结 DSP 全部有效级、w 修正链和所有侧带，禁止只冻结 P 或只冻结 valid。

## 5. 推荐逻辑接口（尚非既有 RTL 端口）

| 信号 | 方向 | 位宽 | 语义 |
|---|---|---:|---|
| clk_i | 输入 | 1 | 运算时钟 |
| rst_i | 输入 | 1 | 本时钟域同步复位 |
| in_valid_i | 输入 | 1 | 本拍有三元组 |
| w_i | 输入 | 8 | 广播权重 |
| x0_i/x1_i | 输入 | 8/8 | 两个空间位置 |
| lane_mask_i | 输入 | 2 | 两个输出位置是否有效 |
| out_valid_o | 输出 | 1 | 解包结果有效 |
| p0_o/p1_o | 输出 | 17/17 | 精确乘积 |
| lane_mask_o | 输出 | 2 | 随数据延迟的掩码 |

核心不提供独立 out_ready；上游按阵列信用决定是否发射，下游保证承接所有在途乘积。输出随时可堵塞的接口应在核心外加弹性 FIFO，并以“FIFO 空闲量 ≥ 在途数 + 新发射量”为准入条件。

tile ID 和 K 计数通常由整阵列共享，不建议在 128 个 PE 中各复制一套 32 位 ID。行/列有效性也可由阵列边界生成并按时序共享。

## 6. 累加器与低 LUT/FF 设计

每个 MAC 单元维护两个 INT32 状态。基线选用 FF 加 fabric 加法器，因为每拍都要对同一地址更新；这属于计算状态，不是低速寄存器表。

| 方案 | 优点 | 代价与适用条件 |
|---|---|---|
| 全并行 FF 累加 | 每路每拍一个乘加，时序和控制最直接 | 16×16 为 8192 位累加状态，另有 256 个加法器 |
| banked BRAM 部分和 | 容量转为 BRAM，适合 tile 溢出与 K 分块 | 需要读改写流水、同址前递、多 bank；不能自动保持全部通路每拍更新 |
| 时分复用 MAC | 减少 FF/加法器/路由 | 相同频率下吞吐下降，必须重算帧预算 |
| 单 DSP 原生累加 | 可以利用 P 寄存器作为累加状态 | 每个独立输出通常占一个 DSP，失去本双乘积打包的节省 |

建议先以 8×16 阵列落地低资源版本，保留 16×16 参数化扩展；不同时引入 RAM 累加和高并行输出，以免无法区分时序、端口和数值故障。

减少 FF 的优先项：移除不必要的完整 acc tile 快照；只保留一个活动上下文；结果排空时用分组行读出；容量型参数表全部 BRAM 化。若要求与下一 tile 重叠，则必须付出另一份部分和状态或能在覆盖前完成迁移的 banked 存储代价。

## 7. tile 开始、结束和掩码

- 建议 first_k 有效拍执行 acc=p，而不是 clr 与 en 同拍然后误丢首项；若复用旧 clr 优先的累加器，tile 清零必须在首个有效乘积到达前独占一个采样沿。
- 无效乘积不更新状态。oc 尾行与 n 尾列由 mask 屏蔽，最终也禁止写出对应字节。
- K 分块边界只暂停和保留部分和；最后一个 K 分块结束前不加偏置、不重定标。
- last_k 指的是最后一个被接受的输入事务；只有其延迟后的乘积完成累加，才能进入 drain。
- 复位清空有效位和活动状态；不能对 BRAM 整表逐项异步复位。

## 8. 溢出域与首层处理

全 signed INT8 的保守界 K×128×128。在 K≤2304 时为 37,748,736，远小于 INT32 正上限。实际 run04 权重/偏置审查得到 max(|acc|+|bias_eff|) 上界为 9,804,150。两者都只覆盖各自明确输入域；新模型应重新计算。

PE 不负责首层零点。首层 X 由 u−128 存储，卷积 padding 填 −128；bias_eff=b_q+128Σw_q，由打包器计算一次。普通层卷积 padding=0；letterbox 灰边的输入存储值为 114−128=−14。三者不能混用。

超出数值域的模型应在导出或描述符验证阶段拒绝，不通过静默 INT32 回绕或提前饱和“修复”。

## 9. PE 与尾部的边界

完整输出顺序：所有乘积 INT32 累加 → 一次 bias_eff 加法（建议 33 位中间）→ INT64 乘 M → RNE 移位 → INT8 饱和 → 可选 SiLU LUT。

RNE 对负数也必须 ties-to-even，例如 −1.5→−2、−2.5→−2；不能统一“加半再右移”。M 是逐输出通道参数，SiLU 表是逐激活层参数。并行 PE 不应各复制 M 乘法器或完整全模型 LUT。

## 10. 资源与验收

每个双乘积 PE 的乘法核心目标为 1 DSP；两路累加仅状态即 64 FF，另有修正加减法和 2 个 32 位加法器。流水寄存、扇出复制、路由和控制另计。具体 LUT/FF 数只能以锁版本综合报告为准。

| 验证 | 必须覆盖 | 通过标准 |
|---|---|---|
| 数学穷举 | 256³ 个 w/x0/x1，包括 −128 | 两路与独立整数乘法逐位相等 |
| 原语仿真 | 真实 DSP48E1 模型、极值、随机、连续和空拍 | 值与采样周期均一致 |
| 复位 | 填充中、末项排空中复位 | 不发布旧事务 |
| 累加 | K=1/27/576/2304、断点续算、清零重启 | 与 INT64 oracle 一致 |
| mask | 单路有效、OC/N 尾块 | 无非法累加及越界写 |
| 停顿 | 输入空拍和输出 FIFO 背压 | 无重复、丢失、错位 |
| 综合 | 启用打包的单 PE 和小阵列 | 乘法核心确为一 DSP/PE |

本轮写作未启动 RTL 仿真或综合。历史算术证据见 [audit_result.json](../4_metrics/logs/2026-09-18_yolo_quant_audit_run01/audit_result.json)，其中 16,777,216 三元组穷举是软件代数验证，不能替代新增流水的原语仿真。

## 11. 实施顺序与追踪

先冻结位域和输入采样定义，再实现单 PE、双路累加、小阵列和尾部接口，最后放大并行度。新 FSM 按项目三段式规范，复位态明确为 IDLE；任何新增一级流水同时修改数据和所有侧带，而不是在顶层猜固定延迟。
