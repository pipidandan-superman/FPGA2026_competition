## 1. 结论摘要

当前 OV5640 被配置为以下工作模式：

| 项目 | 当前状态 | 核心证据 |
|---|---|---|
| 输出接口 | **DVP 8 位并行接口**；MIPI PHY 关闭 | `0x300E=0x58`，`cam_data[7:0]` |
| 输出分辨率 | **640×480，VGA** | `0x3808~0x380B=0x0280×0x01E0` |
| 像素格式 | **RGB565，sequence 1** | `0x501F=0x01`、`0x4300=0x61` |
| 字节顺序 | 首字节 `{R[4:0],G[5:3]}`，次字节 `{G[2:0],B[4:0]}` | 官方 FORMAT CONTROL00 表 |
| 曝光/增益 | **AEC 自动、AGC 自动** | `0x3503=0x00` |
| 图像方向 | 不镜像、不垂直翻转 | `0x3820=0x40`、`0x3821=0x01` |
| 抽样/合并 | X/Y 奇偶增量均为 `3/1`；水平 binning 开启 | `0x3814=0x31`、`0x3815=0x31`、`0x3821[0]=1` |
| JPEG | **未启用并处于 reset/clock-off 组合状态** | `0x3821[5]=0`、`0x3002=0x1C`、`0x3006=0xC3` |
| ISP | LENC、RAW Gamma、BPC、WPC、CIP、Scale、CMX、AWB、SDE 开启；UV average 关闭 | `0x5000=0xA7`、`0x5001=0xB3` |

因此，最准确的模式描述是：**OV5640 工作在 DVP 并行 VGA 640×480 RGB565 自动曝光/自动增益模式，启用水平 binning 与横纵抽样，经过 ISP 色彩处理后输出；JPEG 和 MIPI 输出路径未启用。**

## 4. 接口模式

### 4.1 DVP 启用，MIPI 关闭

`0x300E=0x58` 的官方定义为 MIPI CONTROL00。其 `bit[2]=0` 选择 DVP，`bit[4]=1` 和 `bit[3]=1` 分别关闭 MIPI TX PHY 与 RX/LP 模块。因此当前有效输出接口是 DVP，而不是 MIPI。

`0x3034=0x1A` 的低四位 `0xA` 是 MIPI 10-bit mode 字段，但由于 MIPI 已关闭，这不能被解释为当前图像总线是 10 位。实际 FPGA 接口在 `cam_cap_data.v` 中是 `cam_data[7:0]`，RGB565 通过连续两个 8 位 DVP 字节组成一个像素。

`0x3017=0xFF`、`0x3018=0xFF` 打开包括 VSYNC、HREF、PCLK 和 D 数据线在内的输出 pad。SCCB 地址 `0x78/0x79` 是项目采用的 8 位写/读地址形式。

## 5. PLL、XCLK 与 DVP PCLK

### 5.1 外部 XCLK

Vivado Clocking Wizard 请求值为 25 MHz，但生成参数记录的实际 XCLK 为 **24.03846 MHz**。证据位于 `display_test_clk_wiz_0_0.xci` 的生成摘要和 `C_CLKOUT*_ACTUAL_FREQ` 字段。因此计算时应使用 24.03846 MHz，而不是源码注释中的 24 MHz 或 25 MHz。

### 5.2 可确定的 PLL 参数

| 寄存器 | 值 | 官方字段解码 |
|---|---:|---|
| `0x3037` | `0x13` | PLL pre-divider=`3`；PLL root divider=`/2` |
| `0x3036` | `0x46` | PLL multiplier=`70` |
| `0x3035` | `0x11` | system clock divider 字段=`1`；MIPI scale divider 字段=`1` |
| `0x3108` | `0x01` | PCLK root=`pll_clki`；SCLK2x root=`pll_clki`；SCLK root=`pll_clki/2` |

按手册字段可计算 PLL VCO：

`24.03846 MHz ÷ 3 × 70 = 560.8974 MHz`。

再考虑 `0x3037[4]=1` 的 PLL root `/2`，其下游根时钟量级为约 `280.4487 MHz`。这里仅报告手册明确给出的 PLL 字段关系，不将其直接等同于 DVP 引脚上的 PCLK。

### 5.3 为什么不能认定 PCLK=51 MHz

- `0x3036=0x46` 的官方含义是 **PLL multiplier=70**，不是 `sys divider=4、pclk divider=6`。
- `0x460C=0x20` 的 `bit[1]=0`，手册规定 DVP PCLK divider 由 **auto mode** 控制。
- 只有 `0x460C[1]=1` 时，`0x3824[4:0]` 才是有效的手动 DVP PCLK divider；当前 `0x3824=0x02` 不能单独用于计算 PCLK。
- `0x4837` 位于 MIPI control/timing 章节，官方名称是 PCLK PERIOD，不能当作 DVP 分频寄存器。
- 手册未在这些表项中给出自动 DVP divider 的最终锁定值，也没有当前硬件 PCLK 测量结果。

因此实际 DVP PCLK 未确认，实际帧率也未确认。确定 PCLK 后才可使用：`frame_rate = PCLK / (HTS × VTS) = PCLK / 1,892,000`。

## 6. 输出格式与 FPGA 接收一致性

`0x501F=0x01` 选择 ISP RGB，`0x4300=0x61` 的高四位 `0x6` 选择 RGB565，低四位 `0x1` 选择以下顺序：

1. 第一个 DVP 字节：`{R[4:0], G[5:3]}`。
2. 第二个 DVP 字节：`{G[2:0], B[4:0]}`。

`cam_cap_data.v` 在 HREF 有效期间交替接收两个字节，并执行 `rgb565_data <= {cam_data_d0, cam_data}`，即把第一个字节置于 `[15:8]`、第二个字节置于 `[7:0]`，与官方 sequence 1 完全一致。随后通过位复制将 RGB565 扩展为 RGB888，而不是简单补零。

## 8. 抽样、binning、镜像与翻转

`0x3814=0x31`：horizontal odd increment=`3`，horizontal even increment=`1`。`0x3815=0x31`：vertical odd increment=`3`，vertical even increment=`1`。这确认 X、Y 两个方向都启用了非 1/1 的抽样步进。

`0x3820=0x40` 中 sensor vflip 和 ISP vflip 位均为 0，因此未开启垂直翻转。`0x3821=0x01` 中 ISP mirror 与 sensor mirror 位均为 0，仅 `bit[0]=1`，官方定义为 **horizontal binning enable**。

手册还说明，在 vertical-subsampled format 中 vertical binning 会自动开启。当前 `0x3815=0x31` 明确属于纵向抽样配置，但由于手册没有提供独立可读的 vertical-binning enable 位，本报告只将“纵向抽样”作为直接寄存器事实，将“纵向 binning 自动参与”作为手册描述的行为背景。

## 9. AEC、AGC 与防闪烁

`0x3503=0x00`：`bit[1]=0` 表示 AGC auto enable，`bit[0]=0` 表示 AEC auto enable。因此曝光时间和模拟增益不是固定手动值。

| 项目 | 配置 |
|---|---|
| AEC gain ceiling | `0x3A18/0x3A19 = 0x02F8`（按手册 real-gain 原始格式记录） |
| 进入稳定区上/下限 | `WPT=0x38`、`BPT=0x30` |
| 退出稳定区上/下限 | `WPT2=0x38`、`BPT2=0x26` |
| fast-zone 上/下限 | `0x60`、`0x14` |
| 60Hz maximum exposure | `0x3A02/0x3A03 = 0x17E0` |
| 50Hz maximum exposure | `0x3A14/0x3A15 = 0x1710` |

`0x3C01=0x34` 中 band manual enable 为 0，sum auto mode 和 band counter enable 被置位，说明 50/60 Hz 检测路径采用自动检测逻辑；其阈值、light-meter 和 sample-number 参数由 `0x3C04~0x3C0B` 设置。报告不把这些阈值进一步解释成固定 50 Hz 或固定 60 Hz，因为当前配置没有把 band manual enable 置 1。

## 10. BLC 与 ISP 处理链

### 10.1 BLC

- `0x4001=0x02`：BLC start line=2。
- `0x4005=0x1A`：`bit[1]=1`，BLC always update。
- `0x4004=0x02`：设置 BLC process line-number 参数。
- `0x4000` 未被本表改写；按官方复位值 `0x89`，其 `bit[0]=1`，所以在无其他写入的静态前提下 BLC 默认启用。

### 10.2 ISP 顶层开关

`0x5000=0xA7` 的有效公开位：LENC=1、RAW Gamma=1、black pixel cancellation=1、white pixel cancellation=1、CIP=1。

`0x5001=0xB3` 的有效公开位：SDE=1、Scale=1、CMX=1、AWB=1，UV average=`bit[2]=0`。其余手册标为 debug 的位不作功能推断。

`0x5580=0x06` 进一步表明 SDE 中 contrast 与 saturation 开启，hue、gray、negative 和 fixed Y/U/V 均未开启。`0x5583/0x5584/0x5589~0x558B` 提供饱和度及 UV adjust 阈值。

### 10.3 调校表

| 模块 | 写入范围 | 作用 | 判断边界 |
|---|---|---|---|
| LENC | `0x5800~0x583D`，62 项 | Green matrix、Blue/Red matrix 和 offset | 记录系数，不推测具体镜头型号或校正强度 |
| AWB | `0x5180~0x519E`，31 项 | Advanced AWB 控制、稳定区和 RGB limits | AWB 顶层开关已开启 |
| Gamma | `0x5480~0x5490`，17 项 | Gamma control 与 YST00~YST0F 曲线 | 记录实际曲线节点 |
| CMX | `0x5381~0x538B`，11 项 | Y/U/V color matrix 与 sign | CMX 顶层开关已开启 |
| CIP | `0x5300~0x530C`（未写 0x5308） | sharpen 与 denoise threshold/offset | CIP 顶层开关已开启；未写字段沿用复位值或上电状态 |
| SDE | `0x5580` 等 6 项 | contrast、saturation、UV adjust | 不推测主观画质效果 |

大量 `0x3612~0x3731` 和 `0x3901~0x3906` 地址不在该版本数据手册公开寄存器章节的完整定义范围内。本报告将其标为 sensor analog/internal tuning，仅保存写入值，不采用源码注释或第三方表格猜测语义。

## 11. JPEG 状态

JPEG 未启用的证据不是单独依赖 `0x4713=0x00`，而是多个官方控制位的组合：

1. `0x3821[5]=0`：JPEG enable 清零。
2. `0x3002=0x1C`：JFIFO、SFIFO、JPG reset 位被置位。
3. `0x3006=0xC3`：JPEG 2x clock 和 JPEG clock 对应位为 0。
4. `0x4713=0x00`：不属于手册列出的 JPEG mode 1～6 编码。
5. 输出 formatter 明确选择 RGB565，而不是压缩数据。

`0x4407=0x04` 只是 JPEG quantization scale 参数；在 JPEG enable 清零且编码模块复位/停钟时，它不改变当前输出仍为 RGB565 的结论。

## 12. 源码注释冲突与纠正

| 源码注释倾向 | 官方手册结论 | 审计处理 |
|---|---|---|
| 把 `0x3036=0x46` 解释为 sys/PCLK divider | `0x3036` 是 PLL multiplier，值为 70 | 源码注释错误，不采用 |
| 推导 PCLK 约 51 MHz | 自动 DVP divider 的最终值未知 | 不报告 51 MHz |
| 把 `0x3821=0x01` 称为 mirror on | bit0 是 horizontal binning，mirror 位是 bit2/bit1 | 判定为不镜像、水平 binning 开启 |
| 把 `0x4837` 称为 DVP CLK divider | 手册将其列为 MIPI timing 的 PCLK PERIOD | 不用于 DVP PCLK 计算 |
| 直接把 `0x3824=0x02` 当作当前分频 | `0x460C[1]=0` 时使用 auto mode | 手动 divider 不生效 |
| 把 `0x4713=0x00` 单独解释成 JPEG OFF | 该值不是手册列出的 mode 1～6；JPEG enable/reset/clock 才是决定性证据 | 使用组合证据 |

## 13. 尚不能由静态审计确认的事项

- DVP 引脚上的实际 PCLK 频率。
- 实际帧率、曝光时间和实时增益；AEC/AGC 会动态调整。
- 当前摄像头模组是否逐项 ACK 了全部 SCCB 写入。
- LENC/AWB/CMX/Gamma 参数是否与当前镜头、光源和传感器批次达到最佳匹配。
- 板上 RGB565 字节边沿、HREF/VSYNC 极性及时序裕量。
- 实际显示颜色、图像方向和稳定性。

这些事项需要 SCCB 回读、ILA/示波器测量、单帧抓取或板级运行证据，不能从源码注释或寄存器表静态推导。

## 14. 最终判断

当前工程中的 OV5640 配置不是 RAW、YUV、JPEG 或 MIPI 模式，而是：

> **DVP 8-bit + VGA 640×480 + RGB565 sequence 1 + ISP RGB + 自动 AEC/AGC + 水平 binning + 横纵抽样 + ISP scale/色彩处理。MIPI PHY 与 JPEG 输出路径关闭。**

实际 DVP PCLK 和 FPS 仍为待测参数。本结论仅对本报告所列哈希对应的源码和数据手册版本有效。
