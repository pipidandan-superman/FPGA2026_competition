## 当前版本的关键事实

1. **当前模型运行在 PC CPU。** `gesture_viewer.py` 使用 `YOLO(..., task='detect')`，预测参数显式为 `device='cpu'`、`imgsz=640`、`conf=.45`、`iou=.7`。动作发布门另外要求置信度≥0.75、同一允许类别连续3个不同新推理帧；这两种阈值用途不同。当前不能宣称 Ryzen GPU/NPU、PL 模型或机械臂已经参与。
2. **固定动作位流与蓝牙桥版本分开。** 本图使用 `axi_action_0`，UART 与 LED 均来自动作核心；当前 HWH 不含 `ble_uart_bridge_0`，也不含 `BT_RX/BT_TX`。仓库中已有蓝牙通信证据，但不属于当前动作位流的并行模块。
3. **PS 控制与 PL 搬运分开。** PS 经 `M_AXI_GP0 → axi_smc` 配置寄存器。VDMA 经 `axi_mem_intercon` 访问 HP0/HP1；两条 VDMA 主接口都按地址译码。当前 CMA 帧槽位于 HP1 地址窗，因此读写均走 HP1，不能画成“MM2S 固定 HP0、S2MM 固定 HP1”。PS 不逐像素代转 VDMA 数据，但网络上传前会复制完成槽并做缓存失效。
4. **当前采用软件轮询。** HWH 中 VDMA 两个 `introut` 无连接，ACTL 无 IRQ。完成检查不能画成已实现的 PS 中断服务。
5. **状态寄存器是位图。** `STATUS` bit0=READY、bit1=BUSY、bit2=DONE、bit4=UART_BUSY；发送期间可能读到 `0x12`，不能把 BUSY 状态限定为数值2。`FRAME_COUNT` 是 `EXEC_COUNT` 的映射。`OUTPUT_STATUS` bit0 表示本版串口存在，bit4 表示 UART busy；它不是物理 UART 回环反馈。
6. **内部完成与物理接受不同。** LED 在执行器接受 `start` 时更新；第7个UART字节停止位完成后才产生 `exec_done`。PS 核对寄存器并 ACK 之后发 UDP 完成回执。UART 帧只携带 `seq[7:0]`，完整序号在 UDP/CSR 中保留32位；COM4原始捕获和LED人工确认另有证据。
7. **热重载恢复时序明确。** 当前 `camera.py` 在 PL 下载后等待10秒，最多30秒等首个MM2S槽位转换；清一次启动粘滞位后，再要求2秒内双向出现新槽位变化。10秒是定时等待，不是SCCB、PCLK或VSYNC已健康的独立证明。
8. **控制异常不会保证物理停止。** PC 无有效动作1秒后，在链路健康时发送CLEAR；断联或结果不确定时停止提交，当前PL没有断联watchdog，因此LED可能保持原值。图中CLEAR只对应动作0，不能解释为机械臂急停。

## 实际模块层级补充

02A将视频IP作为功能边界；自研子模块的实例关系如下。名称保留源代码中的实际拼写（例如 `cam_captrue_data`、`iic_protocal`），避免“美化名称”导致查找失败。

```text
display_test（固定发布 HWH）
├─ processing_system7_0
├─ axi_smc（控制互连）
├─ axi_mem_intercon（内存互连）
├─ axi_vdma_0
├─ cam_captrue_data_0 : cam_captrue_data
├─ ov5640_cfg_top_0 : ov5640_cfg_top
│  ├─ u_sccb_protocol : sccb_protocol
│  └─ ov5640_regs : ov5640_regs
├─ v_vid_in_axi4s_0
├─ v_axi4s_vid_out_0
├─ v_tc_0
├─ pix_frame_display_0 : pix_frame_display
├─ hdmi_out_adv7511_v1_0_0 : hdmi_out_adv7511_v1_0
│  ├─ u_rgb2ycbcr422 : rgb2ycbcr422
│  ├─ u_adv7511_cfg_top : adv7511_cfg_top
│  │  ├─ u_adv7511_controller : adv7511_controller
│  │  └─ u_adv7511_iic_data_xfer : adv7511_iic_data_xfer
│  │     ├─ u_adv7511_init_table : adv7511_init_table
│  │     └─ u_iic_protocal : iic_protocal

├─ axi_action_0 : video_axi_action_uart_top

│     ├─ u_slave : axi_lite_slave
│     ├─ u_regs : axi_action_reg_bank
```
