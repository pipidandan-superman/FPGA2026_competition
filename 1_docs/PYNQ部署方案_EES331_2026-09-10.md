# EES-331 上板 Python（PYNQ）部署方案 v1

- 日期：2026-09-10 ｜ 起草：AI 侧成员
- 目标：在 EES-331（Zynq-7020 学校板）上获得 PYNQ 环境（Python3 + Jupyter +
  pynq 库 + Ubuntu 22.04），经网线 SSH/浏览器访问，为后续板端编排/控制类
  Python 代码与 PL overlay 加载打基础。
- 状态：物料已就绪（第 2 节）；移植步骤待板会执行。

## 1. 路线选择

采用 **PYNQ-Z2 官方镜像 + 更换板级启动文件（FSBL/设备树）** 的移植路线，
不走完整 sdbuild 自制镜像（需 Linux 构建机、数小时构建、磁盘消耗大）。

理由：EES-331 的 PS 以太网接线与 PYNQ-Z2 高度一致——RGMII MIO16..27、
MDIO MIO52..53、PHY 均为 Marvell 88E1518（主核支持，设备树大概率免改）；
差异点只有两个，均为已知可改项：

| 差异 | PYNQ-Z2 镜像默认 | EES-331 实际 | 对策 |
|---|---|---|---|
| 控制串口 | UART0 → ttyPS0 | UART1 MIO48/49 → ttyPS1 | 改设备树 console/stdout |
| DDR 容量 | 512 MiB | 1 GiB（MT41K256M16 ×2，32bit） | 改设备树 memory 节点 |

PS 时钟/DDR 时序由 **EES-331 板级验证过的 FSBL** 提供（09-03 DDR 测试
PASS、09-08 以太网链路 PASS 的同一套 PS7 初始化），不使用镜像自带 FSBL。

## 3. 移植步骤（板会执行）

### S1 烧卡
balenaEtcher 选 `pynq_z2_v3.1.1.img` → 写入 TF 卡 → 校验。完成后 Windows
会提示"需要格式化"——**一律取消**（多分区 Linux 布局）。

### S2 制作 EES-331 的 PYNQ 用 XSA（XSA_pynq）
在 09-08 以太网 XSA 基础上**只加 SD0**（PYNQ 需要 SD 启动）：
- SD 0：MIO 40..45（+CD 按板手册；EES-331 GEMM 板级基线已验证过此接法，
  见 `1_docs/Zynq_PS7_Config_Report.md` §9）
- 保留：ENET0（MIO16..27 / MDIO52..53 / 1G / 复位 MIO47）、UART1（MIO48/49）、
  DDR 配置、FCLK0 100MHz
- 导出 `xsa_pynq.xsa`（含 bit）
- 手段：Vivado GUI 改 BD，或复用/扩展
  `4_metrics/logs/2026-09-10_repro_prep_run01/enable_enet0_export_xsa.tcl`
  （SD0 追加 `CONFIG.PCW_SD0_PERIPHERAL_ENABLE=1` 等；遵守 2_fpga 冻结边界，
  先取得用户授权）

### S3 FSBL + BOOT.BIN
1. Vitis 2025.2 由 `xsa_pynq.xsa` 生成 FSBL（`zynq_fsbl.elf`）
2. 从镜像原装 `BOOT.BIN` 提取 u-boot（bootgen 分区拆解/论坛通用做法；
   首次执行时落证据）
3. bootgen 打包新 `BOOT.BIN` = `[bootloader] zynq_fsbl.elf` + `u-boot.elf`

### S4 设备树修正（IMAGE.UB 重打包）
1. `dumpimage` 从 `IMAGE.UB`（FIT）取出 dtb
2. 修改：`chosen/bootargs` 与 `stdout-path` 改 **ttyPS1**；`memory` 节点
   0x20000000 → **0x40000000**（1GiB）
3. dtc 反编译/编译 + `mkimage` 回灌 FIT（建议 WSL Ubuntu 内完成，
   `u-boot-tools` + `device-tree-compiler` 两个包即可）
4. 用新 `IMAGE.UB` + 新 `BOOT.BIN` 覆盖 TF 卡 FAT 分区同名文件

### S5 首次启动与网络
1. TF 卡插入 EES-331，启动模式拨到 SD（按板手册核对拨码/跳线），上电
2. 串口（COM，115200）应见 u-boot → 内核 → 登录提示（`xilinx/xilinx`）
3. 网络：PYNQ 默认 DHCP。两种接法择一：
   - 家里/实验室路由器 DHCP 先 boot 一次 → ssh 进去改静态
     （netplan：`192.168.240.10/24`，或沿用本组网段约定）→ 之后直连 PC
   - 或 WSL `wsl --mount` 挂 TF 卡 ext4 分区预置 netplan 静态配置
4. 验收：PC `ping` 通 → `ssh xilinx@<ip>` → `python3 -c "import pynq,numpy;print(pynq.__version__)"`
   → 浏览器 `http://<ip>:9090`（Jupyter，密码 xilinx）

### S6 PYNQ 侧 PL 联动（后续）
- `pynq.Overlay` 加载冻结 bit（`display_test_wrapper.bit`）验证 PL 可控可加载
- 摄像头/VDMA/UDP 发帧链路在 PYNQ 下是否迁移为 overlay + Python 驱动，
  **另行立项评审**；当前裸机 V3.1.3 链路仍是比赛主链路，不动

## 4. 边界与风险

| 项 | 说明 |
|---|---|
| 板端推理定位 | Z-7020 双 A9 @667MHz 跑 YOLOv8n 不现实；比赛主架构维持"板采图 → UDP → PC 推理"。板端 Python 用于编排、舵机/外设控制、预处理；DPU 路线对 7020 不现实，不立项 |
| 冻结边界 | S2 改 BD 涉及 `2_fpga` 冻结工程，须用户明确授权后执行（或由队友在其已解锁的工作副本上出 XSA_pynq） |
| 未验证项 | u-boot 提取、FIT 重打包、SD 启动拨码、PYNQ 内核对 88E1518 的识别，均属首次执行项，执行时各留证据 run |
| 版本锚点 | PYNQ v3.1.1（Ubuntu 22.04 底座）；若 ttyPS1/DDR 修改遇到问题，回退 PYNQ v2.7 镜像同法移植 |
