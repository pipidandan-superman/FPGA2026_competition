# 具身智能赛道要求速查（提炼自官方选题指南 3.2 节）

> 来源：`competition/amd_fpga_2026_track_guide.pdf`（全国大学生嵌入式芯片与系统设计竞赛 2026 · FPGA 创新设计赛道 AMD 选题指南）

## 1. 系统分工（3.2.1）

| 角色 | 职责 |
|---|---|
| Ryzen AI PC | 端侧 AI 推理、任务规划、人机交互、上层决策与系统调度 |
| AMD FPGA / Zynq | 高速传感接入、实时处理、IO 扩展、运动控制、安全逻辑、低延迟数据桥接 |
| 两端协同 | 通信、数据流、时间同步与控制闭环 |
| Skill / Workflow（加分） | 将部署、硬件调用、模型推理、控制接口与调试方法封装为可迁移能力 |

## 2. 技术链路要求（3.2.2.3）

### AI PC 端（至少一项）
本地 AI 推理 / 图像·语音·传感器·多模态理解 / 任务决策与路径规划 / 上位机控制界面 / 与 FPGA 通信 / 状态监控与日志 / 策略模型运行。
→ 须说明端侧运行的具体收益（降延迟、数据本地化、离线运行、与物理控制实时协同）。

### FPGA/Zynq 端（至少一项，不能只做转接板）
实时 IO 控制 / 电机·舵机·步进电机控制 / 高清摄像头或高速传感器接入 / 10G Ethernet 高速传输 / 实时桥接 / 图像预处理或数据流加速 / 多传感器同步采集融合 / 低延迟安全保护逻辑 / 自定义 RTL·HLS·AXI 外设·Block Design·PYNQ Overlay。

### 两端协同（重点审查）
必须给出通信方式、数据流、时间同步方案，并说明**通信异常时的处理策略**。"简单把两套设备连起来不视为协同"。

## 3. 平台（3.2.2.4 / 3.2.3.2）

| 平台 | 适合方向 |
|---|---|
| KR260 | 高速视觉与实时传输：10G Ethernet、高清摄像头、多路视频、FPGA 侧图像预处理、高速流式传输 |
| PYNQ-Z2 | Python 一体化控制与快速原型：AI 识别 + 舵机/电机控制、Overlay 传感器采集、桌面级原型 |
| SEA | IO 扩展与执行控制：多传感器融合与执行器联动、智能工位、安全监测与实时控制 |

- 上位机：任意 AMD Ryzen AI PC（借用机型：Ryzen AI Max+ 395 / Ryzen AI 9 HX 370，中期报告评审后发 10 台）
- FPGA 侧：任意 AMD FPGA / Zynq / Versal，须声明型号；板卡借用（KR260/PYNQ-Z2/SEA）申请方式另行公告
- AI PC 软件栈：**ROCm 7.14.0 及以上**
- 使用 PYNQ 时：Python 只是统一调用接口，作品仍须包含 FPGA Overlay、PL/PS 协同设计或硬件逻辑

## 5. 优化目标（3.2.4.1）

- 提高任务闭环成功率，降低人工干预次数
- 压缩端到端响应延迟（**看 P95/P99 与最大值，不是平均值**）
- 提高 FPGA/Zynq 可量化贡献
- 降低控制周期抖动与截止期未命中率
- 满足性能与时序前提下合理用片上资源
- 沉淀可复用 Skill / 工作流

## 6. 指标要求（3.2.4.2 ~ 3.2.4.5）

**五类核心必报指标**（每项至少一项可复测数据）：

| 指标 | 口径要点 |
|---|---|
| 任务闭环成功率 | 成功次数/有效测试总次数；须预定义成功、失败、人工干预及测试次数 |
| 端到端响应延迟 | 传感器产生数据 → 执行器实际物理响应；报 P50/P95/P99/最大值；说明测量起止点 |
| AI 任务效果与推理性能 | 分类 Accuracy/Macro-F1；检测 mAP@0.5:0.95；分割 mIoU；导航到达率/碰撞率/路径效率；batch=1，分预处理/推理/后处理/总感知延迟；持续性能用 FPS |
| FPGA/Zynq 可量化贡献 | 处理延迟、吞吐率、控制抖动、CPU 占用、功耗；说明为何转接板/软件方案替代不了 |
| 两端通信性能 | 单向延迟或 RTT（说明时钟同步方法）、有效吞吐率、丢包/错误/重传/指令超时率；实测不用理论带宽 |

**场景专项（至少选报 2 项）**：实时控制（P99 抖动、Deadline Miss Rate、RMSE、超调、调节时间、稳态误差）｜FPGA 数据处理（处理延迟、帧率、吞吐、WNS）｜FPGA 资源使用（LUT/FF/BRAM/DSP）｜视觉与传感（帧率、丢帧率、同步误差）｜系统可靠性（连续运行时间、故障恢复时间、安全状态触发成功率）｜功耗与能效｜Skill 复用（干净环境部署成功率与时间）。

**证据要求**：每项指标注明硬件型号、模型精度、输入规格、软件版本、FPGA 时钟、测试次数/时长、功耗模式；对比须同条件；提供原始日志、测试脚本、示波器/逻辑分析仪证据。

## 7. 提交内容（3.2.5）

工程包四部分：①系统层（架构图、数据流图、模块说明、接口定义）②FPGA 侧（源码、构建 tcl、.bit/.xsa/.hwh、综合报告含资源/时钟/WNS、验证结果）③AI PC 侧（模型来源/版本/量化、应用与通信源码、部署脚本与依赖清单）④硬件外设（清单、图纸/BOM/接线图、供电说明）。

指标汇总表 `metrics/metrics.csv`（官方表头）：指标名称｜类别｜数值｜单位｜测量条件｜测试次数/时长｜证据文件。

设计报告八要素：选题背景与创新点 / 架构与软硬件划分依据 / AI PC 端（模型理由、端侧收益、放弃的候选）/ FPGA 端（为何不可替代）/ 两端协同（协议、数据流、时间同步、异常处理）/ 实测结果（与 metrics 一致）/ 失败分析 / 复现说明。

加分项 Skill（3.2.2.5）：模型部署调用、通信初始化与状态检查、视频流采集/10G 传输调用、Overlay 加载与 IO 控制、执行器控制与安全状态机、任务分解与调试流程；须展示复用（如小车方案迁移到机械臂）。
