## 1. 结论摘要
以下第 1 到第 12 节是冻结前的问题分析记录。它们解释当时为什么优先怀疑 S2MM line buffer、动态 Genlock、PCLK 约束和颜色链路；最终冻结成功的 21:30 版本已经采用 S2MM line buffer 1024，并经板端照片确认可视化显示通过。


当前问题不是一个孤立错误，而是多层因素叠加后的表现。根据现有证据，最合理的分类如下：

| 现象 | 最可能来源 | 证据强度 |
|---|---|---|
| 上板后必须手动复位一次才有 HDMI 信号 | 当前加载/复位流程或 PL 输出链路的复位释放问题 | 已确认存在该现象；精确硬件根因未定位 |
| 彩条曾经只显示顶行 | PS 彩条生成逻辑使用全局像素索引而不是列坐标 | 已确认并修复 |
| PS RGB888 数据曾造成 DDR 边界/花屏风险 | RGB888 为 3 字节连续像素，必须按字节访问并清理完整帧槽 | 已确认并修复 |
| 摄像头早期无显示或 S2MM 立即报错 | 自由运行摄像头 AXIS 流与 VDMA 启动时序竞争，以及 HDMI 复位流程未完成 | 有 UART 证据；启动竞争已确认，完整根因未终结 |
| 摄像头画面有竖条、撕裂、闪烁 | VDMA S2MM 行缓冲深度 `512` 与成功工程 `1024` 不一致，叠加读写帧同步风险 | 配置差异已确认；修复后效果未验证 |
| 摄像头颜色严重失真 | 当前输出链路存在 RGB888 到 YCbCr422 的额外转换，且 RGB565 到 RGB888 的通道映射可能需要单独校准 | 格式链路已确认；颜色根因未验证 |
| 高频噪点 | OV5640 PCLK 实际频率约 51 MHz，而 XDC 将 `cam_pclk` 约束为 24.038 MHz | 配置不一致已确认；对当前板的影响未单独验证 |
| 时钟树格式本身错误 | 不成立 | 2020 工程和当前工程输出频率计划一致 |

当前最高优先级不是继续改 PS 数据填充逻辑，也不是直接改 ADV7511 颜色配置，而是先完成当前动态 Genlock 固件的完整 UART 验证；若闪烁/竖条仍存在，则在明确授权后做单变量 PL 实验：只把 AXI VDMA `S2MM Line Buffer Depth` 从 `512` 改成 `1024`。

## 4. 历史 UART 与关键错误

### 4.1 S2MM 启动错误签名

多次摄像头运行出现：

```text
S2MM_SR = 0x00014810
```

该状态包含的错误/事件位包括：

| 位 | 含义 |
|---:|---|
| Bit 4 | VDMA internal error |
| Bit 11 | SOF early error |
| Bit 14 | Error interrupt |
| Bit 16 | IRQ frame count reached |

此签名说明摄像头 AXIS 流是自由运行的。PS 正在配置或刚启动 S2MM 时，摄像头帧头可能已经到达，产生启动同步竞争。

早期代码只延迟并清除一次启动错误：

```text
VDMA_S2MM_STARTUP_CLEAR BEFORE=0x00014810
VDMA_S2MM_STARTUP_CLEAR AFTER=0x00010000
```

但后续状态又回到：

```text
0x00014810
```

说明这不是一次性的冷启动毛刺，不能只靠清状态解决。

### 4.2 PS 彩条顶行问题已定位

早期彩条逻辑使用整帧全局像素索引决定颜色：

```c
uint32_t pixel = row * width + column;
uint32_t color = color_for_pixel(pixel);
```

640 宽度下：

- 第 0 行 `pixel` 为 0 到 639；
- 第 1 行 `pixel` 从 640 开始；
- 颜色索引超过预设范围后进入默认黑色。

因此显示器表现为第一行彩条、其余黑色。修复方法是垂直彩条只依赖 `column`：

```c
uint32_t color = color_for_pixel(column);
```

该问题已经修复，不再是当前摄像头故障的候选原因。

### 4.3 DDR 清理和 RGB888 连续字节访问问题已定位

RGB888 是每个像素 3 字节连续存储，不能按 32-bit 每像素简单映射。此前 DDR 清理验证曾把 `0x100E1000` 判为失败，本质是没有清理完整 1 MiB 帧槽。

当前帧缓存规划：

```text
FRAME_BUFFER_0 = 0x10000000
FRAME_BUFFER_1 = 0x10100000
FRAME_BUFFER_2 = 0x10200000
FRAME_BYTES    = 0x00100000
WIDTH          = 640
HEIGHT         = 480
STRIDE         = 1920 bytes
```

PS 侧必须按字节清除和填充完整帧槽，避免读改写合并或残留旧数据导致花屏。

### 4.4 手动复位是当前上板流程的必要条件

彩条 A/B 测试证明：程序化加载后不一定立即出现 HDMI 信号，手动复位后显示恢复。因此后续摄像头测试必须固定流程：

```text
1. 加载归档 BIT
2. 运行 ELF
3. 执行手动复位
4. 采集完整 UART
5. 拍摄照片
6. 判定 PASS/FAIL
```

缺少任何一项都不能宣布摄像头显示 PASS。

## 6. 根因候选排序

### P0：S2MM Line Buffer Depth 不匹配

- 现象覆盖：竖条、撕裂、闪烁、部分行异常。
- 证据：当前 512，2020 成功工程 1024，行宽 640。
- 解释：行缓冲不足可能导致 VDMA 在一行数据尚未完整形成或缓冲时出现丢失/重排。
- 状态：配置差异已确认，修复后效果未验证。
- 操作建议：在明确授权后，只修改该参数为 1024，然后重新生成 PL。

### P1：动态 Genlock/TUSER Fsync 未完成板级闭环

- 现象覆盖：撕裂、闪烁、S2MM 启动错误。
- 证据：XCI 为 dynamic master/slave；早期控制字未启用；当前 PS 已改为 `0x000180CB` / `0x0001008B`。
- 解释：摄像头自由运行流与 VDMA 读写帧竞争。
- 状态：PS 已构建，但当前运行缺完整 UART，不能判定。
- 操作建议：先跑完整 UART，不要立刻叠加 PL 修改。

### P2：颜色格式链路和 RGB 通道映射

- 现象覆盖：颜色失真、色度细节损失，可能包括红蓝互换或灰度异常。
- 证据：当前链路明确存在 RGB888 到 YCbCr422 转换；2020 工程是 RGB 直出 TMDS。
- 解释：BT.601 limited-range、4:2:2 色度抽样、RGB565 位扩展、ADV7511 CSC 中的一个或多个因素可能造成颜色偏差。
- 状态：链路已确认；具体颜色根因未隔离。
- 操作建议：等几何稳定后再做颜色单变量实验，不要与 line-buffer 或 Genlock 实验混合。

### P3：`cam_pclk` XDC 约束与 OV5640 实际配置不一致

- 现象覆盖：高频噪点、采样边界误码、颜色位错位。
- 证据：XDC 约束 `cam_pclk` 为 24.038 MHz；OV5640 寄存器注释和 PLL 计算指向约 51 MHz。
- 解释：时序约束频率错误可能使实现工具对摄像头输入域的时序检查不真实。
- 状态：配置不一致已确认；它对当前板错误的具体贡献未量化。
- 操作建议：先完成 line-buffer/Genlock 几何实验；随后用实测 PCLK 或正确约束做单独实验。

### P4：手动复位/加载流程

- 现象覆盖：上板后无 HDMI 信号。
- 证据：归档彩条 BIT 在手动复位后恢复。
- 状态：现象已确认；内部根因未定位。
- 操作建议：固定加载后手动复位流程，避免把它和摄像头采集错误混在一起。

### P5：摄像头 RST/PWDN 未约束

- 现象覆盖：理论上可能无图像，但当前已有图像。
- 证据：当前 J5 约束审计确认 RST/PWDN 未约束；2020 成功工程同样没有约束。
- 状态：降级为低概率或条件性风险。
- 操作建议：只有再次出现完全无数据时才优先检查。

## 8. 当前不宜继续采用的解释

### 8.1 不宜继续归因于“时钟树格式不同”

两边输出频率计划和关键异步 FIFO 设置一致。唯一输入差异是 PLL 参考时钟 50 MHz 与 100 MHz，但输出频率相同。`pclk_x5` 当前被优化是 ADV7511 并行输出架构决定的。

### 8.2 不宜继续归因于“PS 没有给数据”

白色边框、右上角白块和摄像头画面都说明数据链路已经贯通。早期 PS 彩条确实有 bug，但已经定位并修复；不能把历史错误扩大解释为当前所有问题。

### 8.3 不宜继续归因于“同步极性取反”

PL 自定义方块和方框可以正常显示，说明 VTC 输出的行场同步和 ADV7511 输出时序基本成立。同步极性不是摄像头画面撕裂/颜色失真的首要根因。

### 8.4 不宜只靠清 S2MM 状态继续修

`0x00014810` 清除后再次出现，说明自由运行摄像头流和 VDMA 配置存在持续同步竞争。清状态只能作为观测手段，不能作为功能修复。

## 9. 推荐的隔离实验顺序

### 实验 0：固定当前基线

不改任何 RTL/BD/XDC/PS。

流程：

```text
1. 使用归档 BIT：0A9CBC7B9357429FDB42CA6F1E24B39A16C8D432C148A543A035E1C771C271F7
2. 使用当前动态 Genlock ELF：5C9246CED79CA75A713CB7FDF36420F38FE1FEA3FE9E5BF2FDEF4A149B798C65
3. 运行 ELF
4. 手动复位
5. 保存完整 UART
6. 保存稳定照片和异常照片
```

必须出现的 UART 关键行：

```text
VDMA_S2MM_REFERENCE_SEQUENCE_DONE ... MODE=DYNAMIC_MASTER CONTROL=0x000180CB
VDMA_MM2S_GENLOCK MODE=DYNAMIC_SLAVE CONTROL=0x0001008B
VDMA_MM2S_CONFIG_PASS
VDMA_MM2S_FIRST_FRAME_PASS
HDMI_HEARTBEAT ...
PS_HDMI_CAMERA_VDMA_TEST_PASS
```

判定标准：

- 只有照片、没有完整 UART，不能 PASS。
- 如果 60 秒内没有 `CAMERA_STREAM_FAIL`、`S2MM_SR` 无错误、画面无闪烁/撕裂，并且照片归档，才可判几何链路 PASS。
- 颜色是否可接受单独评价，不与几何稳定性合并判定。

### 实验 1：S2MM Line Buffer Depth 单变量修改

前置条件：实验 0 完成且确认闪烁/竖条仍存在；用户明确授权修改 PL。

只改一项：

```text
AXI VDMA S2MM Line Buffer Depth: 512 -> 1024
```

保持不变：

- 时钟树
- XDC
- OV5640 寄存器
- `cam_cap_data.v`
- VDMA 基址、帧槽、stride、控制字
- ADV7511 配置
- `rgb2ycbcr422`
- PS 动态 Genlock 代码

验收：

```text
1. 完整 UART 无 S2MM 错误
2. 60 秒 CAMERA_OK
3. 照片显示竖条/撕裂/闪烁显著减少或消失
4. 白色边框和右上角叠加不变
5. 原始 BIT、新 BIT、ELF、UART、照片全部归档
```

如果该实验消除几何异常但颜色仍失真，则几何问题关闭，进入颜色单变量实验。

### 实验 2：PCLK 约束/实测单变量实验

前置条件：几何异常稳定复现，且用户明确授权 PL/XDC 实验。

可选步骤：

1. 用示波器/ILA/频率测量确认 OV5640 实际 PCLK。
2. 根据 PCLK 与 51 MHz/24 MHz 的实测关系修正 XDC。
3. 不改任何采集 RTL、ADV7511 配置和 VDMA line buffer。
4. 重新实现并对比同一画面。

该实验主要针对高频噪点和采样误码。

### 实验 3：颜色单变量实验

前置条件：几何稳定，只处理颜色。

候选变量必须一次只改一个：

1. OV5640 RGB565 输出顺序。
2. `cam_cap_data.v` 中 RGB565 到 RGB888 的 R/G/B 通道顺序。
3. `rgb2ycbcr422` 的 BT.601/BT.709、full-range/limited-range 系数。
4. ADV7511 AVI InfoFrame 或 CSC 配置。

不要同时改 camera register、capture RTL、CSC 系数和 ADV7511 表。

## 10. 当前证据边界

以下结论不能写出：

1. 不能说摄像头采集显示链路已经 PASS。
2. 不能说动态 Genlock 修复已经板级验证通过，因为缺少完整 UART。
3. 不能说 S2MM Line Buffer Depth 是最终根因，只能说它是已确认的高优先级配置差异。
4. 不能说 YCbCr422 输出链路整体错误，因为彩条已经通过它成功显示。
5. 不能说 PCLK 约束不匹配就是当前全部噪点的原因，因为尚未做单变量板级验证。
6. 不能把 2020 工程的所有配置照搬到当前工程，因为器件封装、HDMI 输出架构和地址映射不同。

## 12. 最终建议

1. 先固定当前动态 Genlock 固件和归档 BIT，补齐完整 UART 和照片；这是当前最小、零修改的实验。
2. 如果几何异常仍复现，授权后只改 `S2MM Line Buffer Depth=1024`，重新生成 PL。
3. 不要在同一轮实验中同时改 line buffer、PCLK、颜色转换、OV5640 寄存器和 ADV7511 配置。
4. 颜色失真要等画面几何稳定后单独排查；当前它不能解释竖条和闪烁。
5. 所有后续 PASS 必须同时具备完整 UART、板端照片、构建哈希、BIT 哈希和固定手动复位流程。
