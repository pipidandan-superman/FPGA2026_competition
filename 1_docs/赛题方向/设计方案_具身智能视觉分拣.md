## 1. 系统概述

### 1.1 一句话定义

锐眼·智行是一套基于 AMD Ryzen AI PC 与 Zynq-7000 FPGA 异构协同的具身智能视觉分拣系统，通过视觉识别目标物体并由机械臂完成物理抓取与分拣，实现"感知→决策→控制→执行"的完整闭环。

### 1.3 分工依据

| 计算任务 | 计算特征 | 分配到 | 原因 |
|----------|----------|--------|------|
| 目标检测推理（YOLO） | 大规模矩阵运算，需要 GPU 加速，模型体积大 | Ryzen AI PC | 需要端侧大模型推理能力，FPGA 资源不足以运行完整 YOLO |
| 位姿估计与抓取规划 | 几何计算 + 路径搜索，需要灵活的编程环境 | Ryzen AI PC | 算法迭代频繁，PC 端开发效率高 |
| 图像采集与预处理 | 确定性流水线操作，需要零抖动实时性 | Zynq PL 端 | FPGA 硬件流水线保证每像素固定延迟 |
| CNN 特征提取 | 卷积并行运算，适合 FPGA DSP 阵列 | Zynq PL 端 | 硬件并行推理延迟远低于 CPU，可量化加速比 |
| 多轴舵机控制 | 微秒级 PWM 生成，需要严格时间确定性 | Zynq PL 端 | 软件 OS 调度无法保证 <1 µs 抖动 |
| 轨迹插值 | 实时几何计算，控制周期内完成 | Zynq PL 端 | 在硬件状态机中实现，避免软件延迟不确定性 |
| 安全保护逻辑 | 超时/碰撞检测，需要硬件级响应 | Zynq PL 端 | 不依赖软件 OS，硬件看门狗 + 急停电路 |
| HDMI 实时显示 | 视频流输出，需要稳定帧率 | Zynq PL 端 | 已有完整 RTL 设计与仿真验证 |

## 2. 与赛题评分标准的逐项对应

### 2.1 具身智能系统完整度（权重 20）

> 赛题原文："看作品是否完成感知、决策、控制和执行闭环。单独的 AI Demo 或硬件控制 Demo 不计为完整闭环。评分参考任务闭环成功率、端到端响应延迟、人工干预次数，以及异常时能否进入安全状态。"

本设计如何满足：

| 闭环环节 | 实现模块 | 可量化指标 |
|----------|----------|------------|
| 感知 | OV5640 采集 → PL 端预处理 → CNN 特征提取 | 图像采集帧率、预处理延迟、丢帧率 |
| 决策 | AI PC 端 YOLO 推理 + 抓取规划 | mAP@0.5:0.95、推理延迟（P50/P95/P99） |
| 控制 | FPGA 多轴 PWM + 轨迹插值 | 控制周期、P99 抖动、截止期未命中率 |
| 执行 | 机械臂物理抓取 | 抓取成功率、定位精度、人工干预次数 |
| 异常安全 | FPGA 硬件看门狗 + 通信超时 → 归位 | 安全状态触发时间、异常恢复时间 |

**闭环链路**：摄像头看到目标 → FPGA CNN 确认特征 → 上传 AI PC → AI PC 识别并规划抓取坐标 → 下发 FPGA → FPGA 插值计算并驱动舵机 → 机械臂完成抓取 → 视觉反馈验证结果。

### 2.2 AI PC 端侧 AI 能力（权重 20）

> 赛题原文："AI 模型应在 AI PC 本地运行，并实际参与感知、理解、规划或决策。可用 Accuracy、Macro-F1、mAP、mIoU、到达率或碰撞率等任务指标说明模型效果。"

本设计如何满足：

| 指标 | 说明 |
|------|------|
| 模型选择 | YOLOv8-n（轻量版，适配端侧推理），在 ROCm 上运行 |
| 效果指标 | mAP@0.5:0.95（目标检测）、抓取成功率（任务级） |
| 推理延迟 | 单样本 batch=1，分别列出预处理、推理、后处理和总感知延迟 |
| 持续性能 | FPS 或 samples/s |
| 离线能力 | 所有推理在本地 GPU 完成，无云端依赖 |

**AI 实际参与的决策**：
1. 识别画面中目标物体的类别（如"螺丝""螺母""垫片"）
2. 定位目标物体的像素坐标并转换为机械臂工作空间坐标
3. 规划抓取顺序（优先级、避障路径）
4. 根据实时反馈调整策略（如抓取失败后重试方案）

### 2.3 FPGA/Zynq 设计质量（权重 25——最高分值）

> 赛题原文："FPGA/Zynq 必须承担实际硬件功能，其作用可以是实时处理、并行计算、降低延迟、提高带宽、扩展接口或保证控制可靠性。评审会结合控制周期、P99 抖动、截止期未命中率、处理延迟或持续吞吐率、时序收敛状态与资源使用情况进行评分。"

本设计如何满足：

| FPGA 功能 | 量化方式 | 为何不能由软件/转接板替代 |
|-----------|----------|--------------------------|
| CNN 特征提取加速 | DSP 资源利用率、推理吞吐率（GOPs）、加速比（vs. PS ARM CPU） | FPGA DSP 阵列并行计算 CNN 卷积层，ARM CPU 串行计算相同模型延迟高出 5-10 倍 |
| 多轴舵机 PWM 控制 | 控制周期（目标 1 kHz）、P99 抖动（<1 µs）、截止期未命中率 | 软件 OS 调度（即使 RT-Linux）的抖动在 µs-100 µs 级，FPGA 硬件时钟精度达 ns 级 |
| 图像预处理流水线 | 像素率、帧率、WNS | FPGA 流水线每像素固定延迟，无软件中断/缓存不一致引入的不确定性 |
| 轨迹插值计算 | 插值周期、插值误差 | 硬件状态机在固定时钟周期内完成，无软件上下文切换开销 |
| 安全保护逻辑 | 安全触发延迟、误触发率 | 硬件看门狗不依赖软件 OS，即使 CPU 崩溃仍能触发急停 |
| HDMI 实时输出 | 帧率、丢帧率 | 已有完整 RTL 设计（ModelSim 仿真 PASS），PL 端直接输出，无 CPU 开销 |

**资源使用率**：将在 Vivado 综合后报告 LUT、FF、BRAM、DSP 使用率，结合性能与时序评估设计合理性。

### 2.4 AI PC 与 FPGA/Zynq 协同（权重 20）

> 赛题原文："关注两端的通信、数据流、时间同步和控制闭环。简单连接两套设备不能视为协同。参考数据包括单向延迟或 RTT、持续有效吞吐率、丢包或错误率、指令超时率、多传感器同步误差，以及通信异常后的恢复或安全处理结果。"

本设计如何满足：

| 协同要素 | 实现方案 | 量化指标 |
|----------|----------|----------|
| 通信方式 | Ethernet（UDP/TCP，待选型确定） | RTT、单向延迟、持续吞吐率 |
| 数据流（上行） | FPGA → AI PC：CNN 特征/检测框坐标、关节角度、执行状态 | 每帧数据大小、上报频率 |
| 数据流（下行） | AI PC → FPGA：目标坐标、抓取策略、轨迹参数 | 指令大小、下发频率 |
| 时间同步 | 硬件时间戳（PL 端计数器）+ 软件时间戳（AI PC 系统时钟），定期校准 | 同步误差（目标 < 1 ms） |
| 异常处理 | 通信超时（FPGA 硬件看门狗）→ 自动归位/急停 → 通知 AI PC | 超时检测延迟、恢复时间 |
| 指令确认 | 每条控制指令带序号和 CRC，FPGA 回执确认 | 指令超时率、重传率 |

**为何不是简单连接**：两端之间存在双向多类型数据流（视频特征上行、控制指令下行、状态反馈上行、异常通知上行），并有硬件级超时保护与自动恢复逻辑，构成真正的协同控制闭环。

## 3. 应用场景与任务定义

### 3.1 场景

**视觉识别与自动分拣**：在工作台面上放置多种类别的小型物体（如不同颜色/形状的积木、零件或标识卡），摄像头识别目标后，机械臂自动将目标物体从起始区抓取并放置到目标区。

### 3.2 任务流程

1. **启动**：系统上电，FPGA 初始化 OV5640、ADV7511、CNN 加速器和舵机控制模块
2. **待机**：AI PC 发送"开始"指令，FPGA 开始实时采集并上传图像
3. **感知**：AI PC 对上传图像执行 YOLO 推理，识别目标类别与边界框
4. **规划**：AI PC 将像素坐标转换为机械臂工作空间坐标，规划抓取路径
5. **下发**：AI PC 将目标坐标与抓取参数下发至 FPGA
6. **执行**：FPGA 硬件轨迹插值器计算各关节角度，驱动 PWM 输出到舵机，机械臂完成抓取-移动-释放
7. **反馈**：FPGA 上报执行状态（成功/失败/超时），AI PC 视觉验证结果
8. **循环**：回到步骤 2，继续识别下一个目标

## 4. 通信方案

### 4.1 物理层

| 方案 | 优点 | 缺点 | 推荐 |
|------|------|------|------|
| Ethernet (UDP) | 带宽高（100M/1G）、延迟低、支持双向 | 需要实现协议栈 | ✅ 首选 |
| UART | 实现简单、调试方便 | 带宽低（115200-921600 bps）、仅适合指令 | 备用/调试 |
| 10G Ethernet | 超高带宽 | 需要 KR260 板卡（当前无） | 未来扩展 |

### 4.2 协议帧格式

```
| 帧头(2B) | 版本(1B) | 类型(1B) | 长度(2B) | 序号(2B) | 载荷(NB) | CRC16(2B) |
```

| 帧类型 | 方向 | 说明 |
|--------|------|------|
| 0x01 心跳 | 双向 | 100 ms 周期，超时 500 ms 判定断连 |
| 0x02 图像数据 | FPGA → PC | CNN 特征或检测框坐标 |
| 0x03 控制指令 | PC → FPGA | 目标坐标 + 抓取参数 |
| 0x04 执行反馈 | FPGA → PC | 各关节角度 + 完成状态 |
| 0x05 异常通知 | FPGA → PC | 超时/碰撞/急停事件 |
| 0x06 模式切换 | PC → FPGA | 开始/停止/归位/急停 |

### 4.3 异常处理

| 异常场景 | FPGA 响应 | AI PC 响应 |
|----------|-----------|------------|
| 通信超时（>500 ms） | 硬件看门狗触发 → 机械臂归位 → 上报异常 | 显示异常提示 → 尝试重连 |
| 指令 CRC 错误 | 丢弃该帧 → 请求重传 | 重发指令 |
| 机械臂碰撞/堵转 | 硬件过流检测 → 立即停止 PWM → 上报异常 | 分析原因 → 调整策略 |
| AI PC 宕机 | FPGA 独立进入安全待机 → 等待重连 | 重启后重新初始化 |

## 7. 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| HDMI 板级验证不通过 | 中 | 高 | 已有多轮调试经验；备选方案为 LCD 屏或仅 UART 状态输出 |
| CNN 加速器适配困难 | 中 | 中 | 可先用 PS 端 CNN（历史工程已验证），后期迁移 PL |
| 机械臂抓取成功率低 | 中 | 中 | 简化任务（大目标、固定位置、单类别）；提高重复次数取统计均值 |
| 通信延迟不达标 | 低 | 中 | Ethernet 方案 RTT 预估 < 5 ms；UART 备用 |
| EES-331 板卡资源不足 | 低 | 中 | XC7Z020 有 220 DSP 和 140 BRAM，CNN 特征提取足够 |
